### 阶段 12-B：RAGFlow 文档元数据应用边界

- 时间：2026-09-03
- 本阶段目标：判断 RAGFlow 文档元数据能否辅助通用实体 Schema 与后续多类型知识检索。
- 设计结论：
  - 文档元数据有助于文档分类、检索过滤、权限范围和版本治理，但不能替代 LangGraph 的意图识别、会话状态和指代消解。
  - 当前采用文档级粗粒度字段：`document_type`、`business_scope`、`entity_type`、`data_scope`、`version`。
  - `课程介绍与适龄建议.md` 同时包含多门课程，不添加单一 `entity_name/course_name`，防止所有 Chunk 被错误标记为同一课程。
  - 只有一份文档只描述一个课程、教师或校区时，才添加精确的 `entity_name`。
  - 检索时采用“有把握时过滤、零结果时取消过滤重试”的策略，避免元数据误判导致漏召回。
- 当前文档建议值：
  - `document_type=course_catalog`
  - `business_scope=public_consultation`
  - `entity_type=course`
  - `data_scope=static`
  - `version=demo-2026-09-01`
- 风险点：RAGFlow 当前编辑的是文档级元数据，它会作用于该文档产生的全部 Chunk；填写元数据后仍需在检索配置或 API 调用中显式使用过滤条件。
- 下一步：先给两份已解析文档增加最小元数据，在检索测试中验证带过滤和不带过滤的召回结果，不修改现有 Chunk 参数。

### 阶段 12-C：RAGFlow 文档元数据价值评估

- 时间：2026-09-03
- 评估结论：
  - 当前仅有两份公开咨询文档时，元数据对答案准确率的直接提升较小，优先级低于源文档质量、切块、查询改写和重排。
  - 当知识库扩展到课程、教师、校区、服务政策、安全健康及内部运营资料后，元数据对检索路由、权限隔离、版本治理和问题审计具有较高价值。
  - 元数据不能替代实体识别、指代消解、会话状态或权限校验；它是这些能力与 RAGFlow 检索之间的过滤桥梁。
- 项目采用原则：
  - 先使用少量稳定的文档级字段，不把所有正文属性元数据化。
  - 只有意图或实体类型置信度较高时才使用强过滤；过滤无结果时进行无过滤降级检索。
  - 多实体汇总文档不设置单一 `entity_name`；单实体文档才设置精确实体名。
- 价值验证指标：比较无过滤与按 `document_type` 过滤两组结果的 Recall@5、MRR、无关 Chunk 比例、回答事实准确率及平均上下文 Token。
- 下一步：完成两份文档的最小元数据标注后，使用固定问题集执行 A/B 对照测试，再决定是否在 LangGraph 中实现动态 metadata filter。
