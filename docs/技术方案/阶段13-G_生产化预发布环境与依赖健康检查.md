# 阶段 13-G：生产化预发布环境与依赖健康检查

## 1. 阶段定位

本阶段建立的是 uPil 的本地 staging（预发布）能力，不代表真实教育机构生产上线。
业务数据、课程资料、学员信息和接口返回均为虚构演示数据。目标是让项目具备接近
生产的环境分层和依赖可观测基础，同时保持 dev/test 环境可以脱离 Docker 和外部模型
独立运行。

## 2. 环境分层

| 环境 | 主要用途 | 数据与依赖策略 |
| --- | --- | --- |
| dev | 快速开发 | SQLite、离线回退、A2A 默认关闭 |
| test | 自动化测试 | pytest、内存数据库、依赖探针注入 Mock |
| staging | 本地预发布联调 | PostgreSQL、MinIO、RAGFlow、独立 A2A 服务按需启用 |

staging 模板位于 D:/uPil/infra/staging/.env.staging.example。模板不包含真实
凭据，实际 staging 配置必须使用未提交的本地文件或密钥管理系统注入。

## 3. 依赖健康接口

新增接口：

GET /api/v1/health/dependencies

响应示例：

{
  "status": "degraded",
  "service": "uPil API",
  "environment": "development",
  "dependencies": {
    "database": "ok",
    "minio": "disabled",
    "ragflow": "not_configured",
    "a2a_learning": "disabled"
  }
}

状态说明：

- ok：探针成功；
- degraded：已启用的依赖出现 unavailable 或 error，但 API 仍可响应；
- disabled：该能力未启用，不作为故障；
- not_configured：可选能力缺少必要配置，不进行探测；
- unavailable / error：已配置但探测失败，具体细节只进入受控日志。

当前探针行为：

- PostgreSQL/SQLite：只读执行 SELECT 1；
- MinIO：显式 MINIO_ENABLED=true 后只列举桶，不创建桶、不上传对象；
- RAGFlow：配置 API Key 和至少一个 Chat ID 后探测基础 HTTP 地址；
- A2A：A2A_LEARNING_ENABLED=false 时返回 disabled，开启后探测子服务健康端点。

## 4. 安全和可靠性设计

1. 健康响应不返回 URL、API Key、密码、Token 或第三方响应正文；
2. 探针使用独立短超时，不阻塞异步请求循环；
3. 探针失败不阻止主 API 启动，避免可选依赖故障造成级联不可用；
4. 启动检查由 DEPENDENCY_CHECK_ON_STARTUP 控制，默认关闭；
5. DSH 不获得 Docker Socket、数据库、RAGFlow 或 MinIO 直连权限；
6. staging 与 dev/test 的依赖配置分离，避免把生产化配置倒灌到测试。
