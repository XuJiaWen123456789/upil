# 阶段 14-D：家长/教师双角色权限模型收缩

## 1. 阶段目标

本阶段将 uPil 的业务身份收敛为 `parent` 和 `teacher`，取消管理员、校区运营及其
后台入口。目标不是减少必要的安全控制，而是让权限模型与“智能客服 + 学情助手”
产品边界保持一致，避免项目继续扩张成财务、排课、教务和校区经营管理平台。

## 2. 为什么取消校区运营端

校区运营人员查看全校区聚合数据属于经营管理系统能力，通常还会继续引出招生漏斗、
收入、退款、排课、教师绩效和跨校区对比。它与当前项目的家长咨询、个人学情和教师
班级学情主链路并不相同，会显著扩大数据权限、页面数量、合规范围与测试矩阵。

本项目保留的核心闭环是：

1. 家长通过 FAQ/RAG 咨询公开课程与服务规则；
2. 家长在身份核验后查看自己孩子的动态学情；
3. 教师查看自己实际授课班级和学员的学情；
4. LangGraph 负责意图路由和工作流编排；
5. 关键指标由后端确定性代码计算，A2A/DSH 只处理脱敏结果的解释与报告组织。

## 3. 双角色权限矩阵

| 能力 | 家长 `parent` | 教师 `teacher` |
| --- | --- | --- |
| 公开 FAQ/RAG 咨询 | 允许 | 允许 |
| 查看单个学员学情 | 仅限显式绑定的孩子 | 仅限自己授课班级中的有效报名学员 |
| 查看班级聚合学情 | 禁止 | 仅限自己授课且属于本人校区范围的有效班级 |
| 上传机构教学素材 | 禁止 | 允许 |
| 审核机构教学素材 | 禁止 | 当前版本允许，后续增加教师内部职责分离 |
| 管理账号、迁移和部署 | 禁止 | 禁止，由部署平台和受控运维流程完成 |

## 4. 家长数据边界

家长访问学员前必须查询 `parent_learners` 显式绑定关系。系统不能因为请求中提供了
`learner_id` 就返回数据，也不能依赖姓名、手机号或自然语言描述推断亲子关系。
不存在与无权限统一返回 404，避免攻击者枚举有效学员编号。

## 5. 教师数据边界

教师访问单个学员必须同时满足三项条件：

1. `ClassGroup.teacher_id` 表明当前教师实际教授该班；
2. `Enrollment.is_active=true` 表明学员当前仍在该班有效报名；
3. 班级 `campus_id` 位于认证上下文的教师校区范围内。

教师读取班级聚合统计时，同样要求班级启用、授课关系匹配和校区范围匹配。任一条件
缺失都失败关闭，不能把空校区解释为“可访问全部校区”。

## 6. 为什么取消校区端后仍保留 `campus_id`

`Campus`、`User.campus_id` 和 `ClassGroup.campus_id` 是数据归属及横向越权隔离字段，
不是校区运营权限。教师调动、数据导入错误或恶意构造班级编号时，仅校验授课关系仍
不够稳健；校区范围作为第二道边界，可以阻止跨校区读取并发现身份配置异常。

## 7. 多层拒绝策略

- HTTP Query、JSON 和 Form 中的 `actor_role` 使用 `ActorRole`，只接受两种角色；
- Demo 认证会回查数据库，角色不匹配或不受支持时返回 401；
- Trusted Header 即使声明 `admin` 或 `campus_operator` 也会被应用侧角色白名单拒绝；
- OIDC JWT 中的角色声明不参与授权，最终角色只读本地数据库；
- 内部 LangGraph 状态或工具若意外携带未知角色，授权层默认返回 False；
- 历史管理员账号及其外部身份映射通过迁移停用，不物理删除审计记录。

## 8. 运维权限与业务权限分离

取消管理员业务角色不代表系统无法维护。数据库迁移、外部身份绑定、配置发布、密钥
轮换和历史数据治理由 CI/CD、Secret Manager、数据库迁移工具及受控脚本完成。这些
能力不应通过家长或教师调用的业务 API 暴露，也不应通过 JWT 中一个高权限角色获得。

## 9. 当前媒体审核权衡

当前版本由教师上传和审核教学素材，家长只可访问已审核的公开素材。由于
`MediaAsset` 暂无 `uploaded_by`、`reviewed_by` 和 `reviewed_at`，同一教师理论上可以
审核自己上传的内容。后续应增加审计字段，并通过 `media_reviewer` 权限声明或“上传者
不得审核本人素材”规则实现教师内部职责分离，而不是重新引入第三种业务角色。

## 10. 验证基线

自动化测试覆盖：

- Query、JSON、Form 对 `admin` 与 `campus_operator` 的 422 输入拒绝；
- Trusted Header 对已取消角色的 401 拒绝；
- JWT 角色声明不能覆盖本地家长或教师角色；
- 家长越权读取其他孩子返回 404；
- 教师跨班、跨校区或缺少校区范围时拒绝；
- 家长不能读取班级聚合统计或管理机构媒体。

## 11. 阶段结论

uPil 当前产品范围明确为家长与教师双角色的智能客服和学情助手。校区只作为数据归属
与教师权限隔离维度，不提供校区运营端、管理员后台、财务后台、排课后台或综合教务后台。
