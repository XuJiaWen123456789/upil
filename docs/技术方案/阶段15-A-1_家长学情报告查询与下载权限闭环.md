# 阶段 15-A-1：家长学情报告查询与下载权限闭环

## 1. 阶段目标

把“在 SSE 对话中临时展示一段报告”扩展为可持续查询的报告资源：家长生成报告后能够获得主系统任务编号，分页查询自己的任务、查看任务状态，并下载经过完整性和内容安全复核的 Markdown Artifact。

本阶段不实现 PDF 渲染、永久公开链接、教师班级报告或后台任务队列。这些能力使用独立阶段完成，避免家长资源权限与教师聚合数据权限混用。

## 2. 业务流程

```text
家长发起报告请求
    │
    ▼
LangGraph 校验家长与学员绑定关系
    │
    ▼
主系统创建 ReportTask（pending → running）
    │
    ▼
A2A 学情分析节点返回 Markdown Artifact
    │
    ▼
编排层执行质量、名称和隐私检查并持久化（completed）
    │
    ├── SSE 返回主系统 report_task_id
    │
    └── 家长按任务 ID 查询详情或下载
```

远程 A2A Task ID 用于执行节点的任务追踪，主系统 `report_task_id` 用于业务资源查询和授权。二者必须分离，否则前端可能拿远程编号访问主数据库，审计系统也无法稳定关联报告所有权。

## 3. HTTP 契约

| 接口 | 作用 | 核心约束 |
| --- | --- | --- |
| `GET /api/v1/reports` | 分页查询报告任务 | 只返回当前家长的 `parent_learning_report` |
| `GET /api/v1/reports/{task_id}` | 查询状态和产物元数据 | 不返回正文、checksum、scope、metrics 和内部异常 |
| `GET /api/v1/reports/{task_id}/download` | 下载 Markdown | 只有唯一且完整的 completed Artifact 可以下载 |

列表默认每页 20 条，允许范围为 1 至 100 条。列表不加载 Artifact 正文，只投影任务摘要；详情只返回安全的产物描述，正文仅在通过最终下载门禁后进入响应。

## 4. 所有权与防枚举

报告服务使用 `task_id + requester_id + task_type` 联合查询，家长所有权和任务类型直接进入 SQL 条件。系统不会先读取其他用户的任务再在 Python 中过滤。

以下情况统一返回 404：

- 任务不存在；
- 任务属于其他家长；
- ID 存在但不是家长学情报告类型；
- 任务编号格式不符合公开契约。

统一响应避免攻击者通过 403、404 或不同错误文案枚举其他家长是否生成过报告。教师不具备家长报告资源权限，访问列表、详情或下载均返回 403。

## 5. 最小化响应

公开任务摘要只包含：

- 主系统任务编号、固定任务类型和状态；
- 报告周期、模板版本和时间戳；
- 是否显示下载入口；
- 固定的状态说明。

响应明确排除 `requester_id`、完整 `scope`、内部 `learner_ref`、统计 `metrics`、远程异常原文、Artifact 正文和 checksum。`failed` 状态只返回固定文案，不能把远程响应、数据库地址或凭据带给客户端。

## 6. 下载前纵深校验

任务状态为 `completed` 只是必要条件，不代表持久化文件一定可信。下载接口还会依次检查：

1. 当前家长拥有该任务，且任务类型正确；
2. 任务处于 `completed`；
3. 任务只有一个 Artifact；
4. Artifact 类型为 Markdown，正文非空；
5. checksum 是合法的小写 SHA-256；
6. 服务端重新计算摘要，并用 `hmac.compare_digest()` 比较；
7. 正文重新通过 `A2AArtifact` 内容安全契约；
8. 正文不包含任务范围中的内部 `learner_ref`。

任一完整性检查失败都返回固定 409，不返回内部失败细节。数据库故障回滚事务并返回脱敏 503。

## 7. 下载响应与审计

下载使用 `text/markdown`，并设置：

- `Content-Disposition: attachment`；
- `Cache-Control: private, no-store`；
- `X-Content-Type-Options: nosniff`。

成功下载会写入 `report.download` 审计事件，只记录当前用户、任务编号、任务类型和产物类型。正文、checksum、scope 和内部学员引用均不进入审计日志。若审计事务提交失败，本次下载返回 503，不在无审计记录的情况下继续发送文件。

## 8. SSE 任务关联

报告生成成功或失败时，SSE 增加：

```json
{
  "stage": "report_task",
  "task_id": "主系统报告任务编号",
  "status": "completed"
}
```

最终 `complete` 事件包含同一个 `report_task_id`。原有 `a2a_task` 事件继续表示远程执行节点任务。普通 FAQ 或非报告学情摘要不返回空的 `report_task_id`，保持既有协议兼容。

## 9. 测试范围

自动化测试使用独立内存 SQLite、独立 TestClient 和本地 A2A Mock，不访问开发机上的 PostgreSQL、OIDC、RAGFlow、MinIO 或真实模型。覆盖：

- 家长列表 SQL 所有权过滤、分页和字段最小化；
- 自有详情、跨家长防枚举、教师拒绝；
- 五种任务状态的下载行为；
- 无 Artifact、多 Artifact、错误类型、错误 checksum 和内部引用泄漏；
- Trusted Header 忽略伪造身份；
- OIDC JWT 经本地身份映射后授权；
- 数据库异常脱敏；
- SSE 主系统任务编号与远程 A2A 编号分离；
- 非报告路由不产生报告专属字段。

## 10. 风险与后续

- Markdown 仍可能被不同客户端以不同方式渲染；当前响应强制下载并设置 `nosniff`，后续 PDF 阶段应使用受控模板而不是浏览器直接渲染不可信 HTML。
- 报告正文目前存储在关系数据库；PDF 和大文件应迁移到 MinIO，数据库只保存对象键、摘要和授权元数据。
- 列表中的 `download_available` 为轻量状态提示，最终是否可下载仍以详情和下载接口的完整性校验为准。
- 当前生成仍为同步 A2A 调用；长耗时生产任务需要消息队列、租约、超时回收和任务恢复。
- 尚未实现报告保留期、删除、撤回、版本替换和对象存储对账。

## 11. 阶段结论

家长学情报告已经从一次性 SSE 文本扩展为有所有者、有生命周期、有最小查询契约、有完整性复核和下载审计的业务资源。当前可以作为 Markdown 报告权限闭环使用，但还不能宣称已完成生产 PDF 报告、异步任务平台或永久文件交付。
