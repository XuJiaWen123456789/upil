# 阶段 15-C：对话式试听与报名线索闭环

## 1. 目标与范围

本阶段在现有多 Agent 对话链上增加报课意向旁路，使家长无需进入独立报名表单即可在正常咨询中表达试听或报名意向。主业务 Agent 继续回答当前问题，报课意向 Agent 只读取同一轮的脱敏文本并提取有限证据；最终强度、队列、授权、幂等和状态迁移全部由后端确定性代码控制。

业务闭环为：

~~~text
家长咨询
  -> 联系方式本地提取并脱敏
  -> 主业务 Agent 正常回答 + 报课意向 Agent 旁路并行分析
  -> 后端确定性分级和幂等写入
  -> 高意向且缺少已授权联系方式时主动询问
  -> 家长在同一轮主动提供联系方式并明确授权后加密保存
  -> 销售顾问老师领取线索、按需查看联系方式并记录跟进
~~~

本阶段明确不建设运营端、运营账号、转化漏斗或 `lead_analytics` 权限，也不接真实 CRM、电话、短信、支付或外部招生系统。销售顾问老师仍是 `teacher`，仅通过 `lead_followup` 最小权限进入线索工作台。

## 2. 为什么采用旁路并行

FAQ、服务规则、学情和报告已有稳定主链路。为了意向识别而把所有节点改造成完整 fan-out/fan-in 图，会扩大改动面，也会让招生旁路故障影响正常答疑。本阶段在 Supervisor 路由前启动独立旁路任务，主链继续处理用户当前问题；主回答完成后只在剩余的短超时预算内等待旁路结果。

旁路模型不可用、超时或结构不合法时，系统使用确定性规则回退。旁路失败不会覆盖主回答、不会向用户暴露异常，也不会自行调用工具或写数据库。

## 3. 意向证据与确定性分级

报课意向 Agent 只能输出课程白名单、意向类型和有限证据码，不能直接输出分数、队列、状态或工具参数。

| 强度 | 典型证据 | 分流 | 是否主动询问联系方式 |
| --- | --- | --- | --- |
| 低 | 想进一步了解 | `lead_pool` | 否 |
| 中 | 明确感兴趣、询问试听流程 | `lead_pool` | 否 |
| 高 | 明确预约试听、明确报名、要求顾问联系 | `advisor_queue` | 缺少已授权联系方式时必须询问 |

例如“舞蹈启蒙班怎么试听？”属于试听流程咨询，只进入线索池；“我想预约舞蹈启蒙班试听”属于明确动作，进入顾问队列并触发固定询问。模型只能补充低风险语义证据；预约、报名、顾问联系、授权和拒绝都必须由本地文本规则直接命中，防止 Prompt 注入推动高风险业务状态。

高意向缺少已授权联系方式时，家长端固定返回：

 > 如果您愿意由销售顾问老师继续确认试听或报名安排，请主动提供手机号或邮箱，并明确同意由销售顾问老师联系您。

文案由后端固定生成，模型不能自由改写。家长端不展示“高/中/低意向”、内部队列或证据码；这些字段只保留给后端分流和销售顾问工作台。这样既保证主动承接明确动作，又避免让家长看到内部销售判断或收到诱导式、不一致的授权话术。

## 4. 联系方式隐私门禁

手机号和邮箱在任何模型或 RAGFlow 调用前由本地代码提取，传给模型的文本只保留 `[联系方式已脱敏]` 占位符。联系方式只有同时满足以下条件才保存：

1. 当前轮主动提供可识别的手机号或邮箱；
2. 当前轮包含明确的记录或联系授权；
3. 当前会话已有意向，或当前轮同时包含明确试听/报名动作；
4. 线索强度为高。

因此，“同意 + 联系方式”不能在没有任何已有意向时凭空创建线索；只给联系方式未授权时也不会保存，系统会要求在同一条消息中重新提供并明确授权。拒绝或撤回优先级最高，会关闭当前会话线索并清除联系方式字段。

联系方式使用 Fernet 加密保存，HMAC-SHA-256 指纹只用于受控去重，普通列表和详情只返回脱敏值。明文只能通过独立接口在重新鉴权后查看，且顾问必须先显式领取线索；响应设置 `private, no-store`、`no-cache` 和 `nosniff`，前端仅在当前页面内存保存，切换、刷新或离开即清除。生产启动时强制校验 Fernet 密钥和至少 32 字节的指纹密钥。

## 5. 权限与状态机

只有 `teacher + lead_followup` 可以访问线索接口。普通教师、家长以及仅有媒体权限的教师均被拒绝。未分配线索可领取；领取后只允许所属顾问查看联系方式和继续跟进。越权详情与不存在资源统一返回 404，避免枚举。

销售顾问与授课教师虽然复用 `teacher` 认证角色，但前端能力画像保持互斥：销售顾问只下发 `lead_followup`，不下发 `class_summary_read`。因此顾问工作台不显示班级统计导航，直接输入班级页面地址会由路由守卫返回对话页；后端班级授权也显式拒绝带 `lead_followup` 的顾问上下文，避免仅靠前端隐藏产生越权。

接口如下：

~~~text
GET  /api/v1/leads
GET  /api/v1/leads/{lead_id}
GET  /api/v1/leads/{lead_id}/contact
POST /api/v1/leads/{lead_id}/follow-ups
~~~

客户端不能直接提交任意状态，只能提交领取、联系、安排试听、确认报名和关闭等有限动作及匹配结果。数据库保存只追加的 `LeadFollowUp` 历史；关键动作写最小审计元数据，不记录家长原文、密文或明文。

## 6. 数据与幂等

`EnrollmentLead` 保存家长/可选学员关系、课程、意向类型、强度、分流、状态、会话引用、受控证据码、加密联系方式和顾问归属。活动线索使用家长、学员、课程和意向类型生成稳定摘要键，并由 PostgreSQL 部分唯一索引阻止重复活动记录。

生产迁移 `005_add_enrollment_leads.sql` 创建线索和跟进表，同时清理早期草案中的 `lead_analytics` 与历史 `T1005` 运营账号。迁移不硬编码插入演示顾问；本地 Seed 只为演示创建 `T1004` 及 `lead_followup`。

## 7. 前端闭环

家长聊天页消费独立 `lead` SSE 事件，仅展示课程、状态、脱敏联系方式和后端固定提示，不展示意向强度、内部队列或证据码。销售顾问老师 `T1004` 在教师端看到“销售线索”入口，可切换顾问队列和线索池，查看强度和分流、领取线索、按需查看已授权联系方式、记录联系结果、安排试听、确认报名或关闭线索。

前端能力和路由守卫只改善体验，后端每个接口仍重新认证和授权。系统没有运营导航、漏斗页面或管理员入口。

聊天页对疑似手机号或邮箱的用户消息增加展示期擦除：请求期间允许该原文作为本次请求体发送，服务端完成处理后立即在浏览器内存和 DOM 中替换为“已提交联系方式（原文已隐藏）”。前端不判断联系方式是否有效、是否授权或是否可以入库，这些仍由后端专用路由负责；页面最终只展示后端安全投影中的掩码，避免浏览器聊天记录长期保留联系方式明文。

## 9. 真实聊天回归补充：多轮状态优先级与动态数据门禁

### 9.1 已确认槽位优先于追问

课程咨询属于“槽位逐步补全”而不是每轮重新问卷。若同一轮已经出现孩子年龄和“没有编程基础/零基础/没有学过图形化编程”等明确表达，编排层直接调用课程目录规则生成推荐：12 岁零基础优先少儿编程基础班。只有基础信息缺失、表达不确定或出现“没做过完整项目但学过 Scratch”等组合时，才继续询问或推荐项目实践班评估。

这条优先级必须位于通用 FAQ/RAGFlow 之前，否则模型容易机械复用“请问是否学过 Scratch”的旧追问，造成家长已经回答后仍被重复询问。

### 9.2 线索等待状态优先于普通问答

线索卡之后的下一轮不是普通新问题，而是一个受控补全状态：

~~~text
本地联系方式提取与脱敏
  -> 查询当前家长 + 当前会话中可补充联系方式的活动高意向线索
  -> 命中：校验格式、同轮授权、更新原线索
  -> 未命中：才进入 Supervisor/FAQ/普通 Agent
~~~

这样家长发送手机号、邮箱、同意或错误格式联系方式时，不会返回欢迎语，也不会凭空创建一条没有课程上下文的线索。可补充状态覆盖首次等待授权，以及跨会话复用后仍在跟进中的活动高意向线索；已报名和关闭终态不会被联系方式消息重新打开。授权与联系方式仍是两个独立门槛：只发号码不保存，只发“同意”也不保存，必须在同一条消息中同时提供合法联系方式和明确授权。

### 9.3 实时排课与名额不能由 FAQ 推断

实时门禁不只匹配“还有名额/实时排课”这些完整术语，还覆盖家长实际使用的口语：

- 有具体班吗、有没有班次；
- 现在有名额吗、有空位吗、目前还能报名吗；
- 周末上午/工作日晚上/这个时间有班吗。

确定性规则要求命中“可用性目标 + 当前性/时段/有无疑问”的组合，并保留静态课程规则的例外：“什么时候上课”“一周上几次”“单节课多长”仍可由课程目录或 FAQ 回答。命中实时门禁后统一路由到 `human_handoff`，回答只能说明需要销售顾问老师结合当前安排确认，不能返回静态旧话术、缓存名额或模型猜测。

### 9.4 跨课程回归矩阵

| 方向 | 纠错/基础 | 插话 | 实时问题 | 联系方式 |
| --- | --- | --- | --- | --- |
| 编程 | 12 岁零基础改问项目实践班 | 请假 | 有空位吗 | 手机号 + 授权 |
| 舞蹈 | 5 岁、零基础 | 请假 | 这个时间有班吗 | 手机号 + 授权 |
| 美术 | 创意班纠正为素描班 | 调课 | 工作日晚上有具体班吗 | 邮箱 + 授权 |
| 音乐 | 8 岁合唱班 | 调课 | 现在有名额吗 | 手机号 + 授权 |

四条链路均验证课程实体、年龄/时段槽位、服务规则路由、实时数据边界、试听主回答、原线索更新和明文不泄露。

此外增加跨会话复用专项：同一家长在新会话重复预约同一课程时复用原活动线索并更新会话引用；即使原线索已经保存过授权联系方式，后续更正联系方式仍由本地补全门禁承接。最终后端全量为 `514 passed, 8 skipped, 3 warnings`。
