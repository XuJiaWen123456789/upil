# 项目收尾：Agent 上下文与记忆治理方案

## 1. 目标与范围

本阶段解决多轮客服场景中的上下文连续性、长期偏好治理、隐私隔离和多 Agent 协作边界，不把“记忆”简单等同于向量数据库。

当前 uPil 的核心约束如下：

- FAQ、服务规则、学情查询、报告和报名意向仍由同一个 FastAPI 应用编排；
- 不使用 A2A/DSH，Agent 通过同进程 ContextEnvelope 共享受控上下文；
- RAGFlow 继续负责知识库解析和检索，长期记忆不写入 RAGFlow；
- 联系方式、Token、密码、身份证、银行卡、数据库主键和动态学情事实不能进入共享上下文、摘要、普通日志或通用长期记忆；
- 未配置嵌入模型时，主聊天、短期会话和结构化偏好仍可工作，情景记忆保持关闭，不用未经评测的临时检索替代它；
- 生产 Python 文件以 500 行左右为目标，650 行触发职责复核，800 行作为禁止合入的门禁。

## 2. 四层记忆在 uPil 中的映射

### 2.1 工作记忆

工作记忆是单次请求内的 ContextEnvelope。它包含认证主体、当前消息、重写后的检索问题、白名单路由、当前实体、受控业务事实、RAG 来源投影和 Agent 结果边界。

ContextEnvelope 使用不可变 dataclass。FAQ、服务规则、学习分析和招生意向 Agent 只能通过 projector 读取自己需要的字段，不能直接改写共享对象。Agent 想提交答案或状态更新时，必须返回 AgentResult，再由 reducer 按白名单归并。

工作记忆不承担长期存储职责，也不把模型猜测升级成权限结论。动态课时、出勤、班级、报告状态和名额必须在需要时重新查询授权业务工具。

### 2.2 短期会话记忆

短期会话记忆位于 backend/app/memory/conversation/，负责多轮指代消解和槽位连续性：

- active_entity：当前课程或班级实体；
- child_age、programming_foundation：当前咨询的有限槽位；
- pending_intent：等待下一轮补充周期的受控意图；
- recent_turns：最近若干条已脱敏用户/顾问消息；
- rolling_summary：被压缩的较旧轮次摘要；
- version 和 TTL：并发更新与过期治理。

短期会话不保存联系方式、知识库正文、课时余额、出勤、报告状态或班级名额。摘要只是恢复话题的线索，不是业务事实来源。

自动化测试和显式离线工具使用 InMemoryConversationStore；当前本地运行、staging 和多进程部署使用 RedisConversationStore。Redis 键包含租户、用户、角色和会话 ID 的哈希，不能只使用浏览器传来的 conversation_id。uPil 使用独立 Redis 容器和数据卷，不复用 RAGFlow 的 Redis/Valkey；本机端口为 16380，staging 容器通过 `upil-redis:6379` 访问。

### 2.3 语义记忆

当前长期记忆采用 PostgreSQL/SQLAlchemy 结构化表 agent_structured_memories，不是向量库。只允许三个稳定、非敏感的白名单字段：

- course_interest；
- class_time_preference；
- child_nickname。

结构化长期记忆有两条准入路径：用户明确说出“请记住、以后记得、帮我记一下”等表达；或者消息对低敏感白名单字段形成高置信度、稳定、肯定的陈述，例如“孩子喜欢编程”“孩子小名叫果果”“孩子喜欢周末上课”。后者由确定性规则识别，不额外调用模型，置信度必须不低于 0.85。联系方式、密码、身份证、银行卡、Token、动态课时、出勤、名额、报告和学情状态会在候选层和策略层双重拦截；“可能喜欢”“暂时喜欢”“明天上午有空”等不确定或临时表达即使带有“请记住”也不会写入。

写入采用版本治理：同一完整作用域下同值去重；自主判断只允许填补空白或命中同值，发现与已有偏好冲突时安全跳过，不能静默覆盖；用户明确要求记住或修改时，才把旧 active 版本标记为 invalidated 并新增版本。用户删除后保留历史记录，允许在同一租户、用户、角色和学员作用域内恢复。learner_id 为 NULL 时使用 SQL IS NULL，避免 NULL 比较导致删除/恢复边界失效。

Agent 只收到 key/value 安全投影，不收到记忆主键、版本、来源会话、租户或授权元数据。新会话按租户、用户、角色和学员作用域读取，不依赖旧 conversation_id，因此可以继承旧会话确认的偏好。FAQ 只在课程推荐或上课时间选择问题中追加课程兴趣、时间偏好提示；昵称不参与检索，价格、名额、校区、服务规则和动态学情也不受长期偏好污染。

### 2.4 程序性记忆

程序性记忆不是用户数据，而是代码化的业务 SOP、Prompt 资源、工具契约和权限门禁。例如：route_for_intent 只允许受控路由；学情统计由 SQL 和确定性聚合计算；报告由固定模板生成 PDF；报课意向由证据契约、确定性状态机和联系方式授权规则处理。

程序性记忆通过版本化代码和测试固化，不把同一套 SOP 每轮重新交给模型自由规划。

## 3. 上下文读取链路

一次聊天请求的读取顺序如下：

1. 认证层得到不可变 AccessContext；
2. 入口对用户消息中的手机号、邮箱等联系方式做本地脱敏，原文不进入模型；
3. 会话存储读取最近轮次、滚动摘要、当前实体和待补槽位；
4. 若请求带 learner_id，先通过 can_access_learner() 检查家长绑定或教师授课关系；
5. 结构化记忆服务按租户、用户、角色和学员作用域读取 active 偏好；
6. assemble_context() 对消息、摘要、轮次和偏好再次做长度限制；
7. 各 Agent 通过 projector 获取最小字段；
8. FAQ 走 RAGFlow 来源链，动态学情走受控数据库工具，招生意向旁路只读取脱敏文本；
9. 各 Agent 返回 AgentResult，由 reducer 合并答案、来源和允许的状态更新。

这里没有把所有历史一次性塞进 Prompt。结构化事实走精确查询，短期话题走窗口和摘要，机构知识走 RAGFlow。三者来源和可信度不同，不能混成一份无限增长的文本。

## 4. 上下文压缩策略

短期记忆使用确定性滚动压缩，不额外调用模型：

- 最近轮次保留原始消息，避免“这个课程”“他”“上一个班”等指代丢失；
- 超出窗口的旧轮次转成按轮次排列的摘要行；
- 摘要设置近似 token 预算，超过预算从较旧摘要行开始裁剪；
- 总上下文超预算时，先淘汰最旧的原始轮次，至少保留最近两轮；
- 用户消息和顾问消息在进入摘要前必须已经过脱敏和长度限制；
- 摘要只用于话题恢复，不能直接驱动课时、出勤、报告状态、名额等动态业务结论。

token 估算采用中英文混合文本的保守近似，不绑定具体模型分词器。后续如果模型供应商和成本指标稳定，可替换为模型对应 tokenizer，但不改变“有预算、有限窗口、动态事实重新查询”的边界。

## 5. 写入链路与治理

### 5.1 短期记忆写入

聊天请求完成后，短期状态在会话存储的原子处理边界内更新。Redis 使用主体隔离键和分布式锁；锁使用独立短租约，不与 30 分钟会话 TTL 绑定，避免进程崩溃后锁长期残留。read() 是纯读取，不刷新 TTL、不增加版本。批量清理会话时过滤 :lock 键，避免清理操作破坏并发互斥。Redis 模式会在应用运行时初始化时执行 Ping；依赖缺失、鉴权失败或服务不可达时显式失败，不能悄悄退回内存。

### 5.2 结构化长期记忆写入

写入流程为：

1. 只接受已经脱敏的用户消息；
2. 判断是显式“记住”请求，还是白名单字段的高置信度稳定陈述；
3. 从确定性白名单模式中提取一个最明确候选；
4. 拦截敏感信息、动态业务事实、不确定表达、否定偏好和临时安排；
5. 校验完整主体与学员权限；
6. 同值去重；自主冲突安全跳过，显式修改才版本化；
7. 事务提交并保留最小来源元数据；
8. 后续读取只输出安全投影，并允许新的 conversation_id 继承。

仓库配置默认值仍保持关闭，避免测试或离线导入时隐式写数据库；本地、staging 和 production 环境模板已经显式设置 MEMORY_WRITE_ENABLED=true。当前本机已执行 007 增量迁移并完成 PostgreSQL 写入及跨会话读取冒烟验证。读取、授权或写入失败只记录固定原因码并回滚记忆事务，返回空投影或 False，不影响已经生成的主回答和 SSE 完成事件。

### 5.3 情景记忆写入

情景记忆只保留协议、门面和 NoopEpisodicMemoryStore。它要求调用方先完成脱敏和准入，默认不写入、不召回。原因是当前项目没有经过评测的嵌入服务、召回数据集和遗忘策略；贸然把所有聊天向量化会污染召回并增加隐私治理面。

因此“没有配置嵌入模型时功能仍完整可用”是当前设计结果，不是主链路缺陷：核心问答依赖短期会话、RAGFlow 和确定性业务工具，稳定偏好依赖结构化表，情景记忆在具备评测条件后再单独启用。

### 5.4 真实聊天中的显式记忆前置与课程槽位复用

为避免历史 FAQ 文案否定已经启用的长期记忆能力，聊天入口先对脱敏消息执行显式记忆命令识别。
命中“请记住、以后记得、帮我记一下”等命令时，直接进入记忆路由，绕过 FAQ/RAGFlow；
只有 StructuredMemoryService 完成候选准入、权限校验和 PostgreSQL commit 后，才向家长返回
确认文案。关闭、拒绝、未授权和存储异常都不会返回“我记住了”。

课程多轮咨询另外维护 child_age、programming_foundation、class_time_preference 等
受控槽位。显式记忆命令只负责写长期偏好，不清空当前会话槽位；时间偏好由独立的窄规则工具
统一解析并写入内存/Redis、请求 Envelope 和课程回答。这样在“我想了解编程课 → 12岁 →
孩子喜欢编程 → 请记住孩子喜欢编程 → 我们周末上午方便上课”中，最后一轮可以复用编程方向
与年龄，同时只提示实时班次仍需课程顾问确认。时间偏好只有在本轮解析到新值时才覆盖，避免
普通追问把已有时段重置为空。

## 6. 多 Agent 共享上下文的价值和边界

共享上下文的价值是避免 FAQ Agent、服务规则 Agent、学习分析 Agent 和报课意向 Agent 各自重新解析同一轮消息，同时避免把一个可变大字典直接暴露给所有节点。

具体机制是：

- Supervisor/入口装配不可变 Envelope；
- projector 按职责生成窄投影；
- Agent 只能返回结构化结果；
- reducer 按白名单合并；
- 路由、身份、权限和主体范围不在 Agent 可写字段内；
- 冲突被记录为固定结构，不让后执行 Agent 静默覆盖前一结果。

这实现的是同一请求内的受控共享上下文，不是跨请求、跨用户共享记忆，也不要求每个 Agent 都是独立进程。当前同进程架构比重新引入 A2A 更适合单代码库、单权限域和单部署单元的项目边界。

## 7. 隐私与业务事实隔离

联系方式在模型前脱敏，招生线索功能另有独立的加密和授权链路；它们不进入 ContextEnvelope、滚动摘要、结构化长期记忆、情景记忆、RAGFlow 或普通日志。

动态学情事实不进入长期记忆：即使用户说“记住还剩 5 节课”，也会被拒绝。下次询问仍必须依据当前绑定关系和数据库状态重新计算。

## 9. 会话历史持久化与 Redis 恢复扩展

### 9.1 为什么同时使用 PostgreSQL 和 Redis

会话历史与工作记忆的生命周期和访问模式不同。PostgreSQL 负责用户可管理的会话目录、脱敏消息和受控恢复快照，支持列表、继续、重命名和删除；Redis 负责高频读写的当前实体、已确认槽位、pending、滚动摘要和最近窗口。这样既不会把数据库消息表当作每轮模型上下文，也不会因 Redis TTL 到期让用户在继续旧会话时完全失忆。

### 9.2 主体隔离和所有权门禁

会话的可信作用域为：

~~~text
tenant_id + owner_user_id + owner_role + conversation_id
~~~

所有者只能来自认证后的 `AccessContext`，创建请求不接受 owner 字段。列表、消息读取、重命名、删除以及聊天续接都必须同时匹配完整作用域；不存在和越权统一返回 404。聊天路由在构造 `StreamingResponse` 前完成校验与恢复，避免 SSE 响应头发送后才发现错误。

### 9.3 恢复算法

每次回答完成后，系统把 Redis 中 `ConversationMemory` 的白名单字段写入 `context_snapshot`，并把脱敏后的 user/assistant 可见文本按序号持久化。继续旧会话时：

1. 先校验数据库会话属于当前主体；
2. 读取有限数量的最近消息；
3. 若 Redis 状态非空，直接使用 Redis，禁止旧快照覆盖；
4. 若 Redis 为空，从 `context_snapshot` 恢复实体、槽位、pending 和摘要，再补入少量最近消息；
5. 后续 Prompt 仍受最近窗口和 token 预算控制，不会全量重放数据库历史。

### 9.4 消息脱敏与删除语义

聊天入口先移除联系方式，持久化边界再移除手机号、邮箱、Token 和内部服务地址，形成纵深防御。邮箱边界只按 ASCII 邮箱字符判断，避免中文紧邻邮箱时 Unicode `\w` 造成漏匹配。前端在联系方式请求结束后把当前 DOM 中的原文替换为安全占位文案。

删除会话会删除 `chat_messages`、`chat_conversations` 和 Redis 短期键，但招生线索、报告任务/产物和结构化长期偏好是独立业务记录，不随聊天历史删除。PostgreSQL 外键设置级联，同时仓储显式删除消息，以保证 SQLite 测试和未来迁移遗漏时也不会残留孤儿消息。

## 10. 长期偏好写入开关与显式读写分离

结构化长期记忆是可选能力，部署环境必须显式开启 MEMORY_WRITE_ENABLED=true。
开发根目录 .env 与 staging 私有环境文件是两个独立配置源，只修改前者不会影响
18000 端口上的 staging 容器。应用启动后应通过运行时配置和依赖探针同时验收，
避免“代码已实现但部署开关关闭”的假故障。

显式记忆写入和记忆读取使用不同语义门禁：

1. 写入只接受句首祈使表达，例如“请记住、帮我记一下、以后记得”；
2. “以前记住的、你还记得吗、根据已记录偏好”等属于读取或引用，不能因为含有
   “记住”二字被当成新的副作用命令；
3. 写入由准入策略、权限和数据库事务决定是否成功，只有 stored 才确认；
4. 读取先取得 PostgreSQL 中按租户、认证用户、角色和学员过滤后的安全投影；
5. 用户明确引用偏好做课程推荐时使用确定性回复，避免外部 FAQ 知识库的旧话术
   否定应用当前能力；普通推荐仍可把安全投影附加到检索 Query。

该设计把“是否拥有记忆”视为应用事实而不是生成式知识。RAGFlow 负责课程与机构
资料，不能决定结构化偏好是否存在。偏好只能影响推荐方向，不能覆盖实时排课、价格、
名额或动态学情数据。

## 11. 配置治理与真实依赖验收

### 11.1 配置源边界

uPil 同时存在开发根 `.env`、staging 私有环境文件、生产模板和 RAGFlow 编排环境。应用 Settings 只解析自己认识的字段；独立配置审计器负责发现废弃字段、模板漂移和跨组件约束。没有对共享根 `.env` 使用 `extra="forbid"`，因为 Docker Compose 与 RAGFlow 合法变量并不都属于 API，强制禁止会让边界错误地耦合。

受管环境的核心契约是：会话后端必须为 Redis；Redis URL 必须存在；结构化长期记忆写入必须显式开启；PDF 开启则 MinIO 及其凭据必须完整；RAGFlow 任何一项出现时，API Key 与两个 Assistant ID 必须成组存在。情景向量记忆仍未启用，启动时 fail-fast，避免出现配置写了但代码链路未验收的假能力。

### 11.2 浅探针与深探针

浅探针验证数据库、Redis、MinIO、RAGFlow HTTP 和结构化记忆表，适合容器健康检查。深探针真实向公开咨询和服务规则 Assistant 各发一个受控问题，覆盖 Ollama Embedding、向量索引、RAGFlow 会话和回答模型，只返回 `ok/unavailable/error/not_configured`，不返回问题、答案、来源、Chat ID、模型或异常详情。

深探针不会加入高频负载均衡检查，因为真实问答有推理成本且存在模型冷启动。基础设施脚本会进一步确认 `bge-m3:latest` 已安装，并从 RAGFlow 容器访问 `host.docker.internal:11528`，解决“首页能开但检索失败”的盲区。

### 11.3 PDF 与 MinIO 强一致边界

开启正式 PDF 后，任务只有在 PDF 渲染、完整性检查、私有 MinIO 上传和产物元数据提交全部成功后才进入 completed。下载时重新校验请求者、当前家长绑定、产物元数据、MinIO 对象和 PDF 魔数。MinIO 不可用不能悄悄回退成本地临时文件，否则多实例下载和权限审计会失去一致性。

### 11.4 真实冒烟与数据回收

真实冒烟使用空白家长 P1008/L1009，验证 Redis 多轮上下文、PostgreSQL 结构化偏好跨会话继承、RAGFlow 双知识域、PDF 上传下载和 P1002 越权 404。结束后按本轮 task/conversation/resource ID 删除 MinIO 对象、审计、产物、任务、偏好和会话；不使用按表清空或删除卷。精确回收既保护其他测试数据，也验证了各领域生命周期边界。

## 12. 字段级长期记忆读取

长期记忆的“写入成功”和“自然问法能读取”是两条独立链路。结构化偏好写入 PostgreSQL 后，读取服务先按 `tenant_id + owner_user_id + owner_role + learner_id` 生成安全投影，再通过固定白名单识别用户询问的字段。当前只允许读取课程兴趣、上课时间偏好和孩子昵称。

用户询问“还记得孩子的小名吗”时，Supervisor 即使给出 UNKNOWN/clarification，编排层也会在执行澄清节点前检查安全投影。明确命中后按 `faq/workflow` 返回确定性文本；问哪个字段只返回哪个字段，不将全部画像暴露给回答模型。该路径不调用 RAGFlow，不让模型自行选择数据库 key，也不把问句写成新的长期记忆。没有值时返回明确的未保存说明。普通 FAQ 和人工转接等路由不受影响。
