# 家长实时学情与报告入口分流

## 1. 问题背景

家长说“查看阶段反馈”或“查看学习报告”，表面都包含“查看”和“学习”，但业务副作用完全不同：

1. 实时学情需要查询当前家长有权访问的数据库快照；
2. 历史报告只需要打开已有报告列表；
3. 生成报告会创建任务、生成 PDF 并写入私有对象存储。

如果三者都交给 FAQ 或由模型自由分类，就会出现只返回通用说明、错误创建报告、要求用户提供内部编号等问题。

## 2. 分流设计

Supervisor 对高风险业务表达执行确定性守卫：

```text
家长消息
  ├─ 查看学习情况/阶段反馈/最近表现 -> learning_summary
  ├─ 查看学习报告/历史学情报告     -> report_history
  └─ 生成学习报告/导出学情报告     -> learning_report
```

三类守卫命中后不调用意图模型，避免模型输出波动改变数据库查询或任务创建副作用。

## 3. 家长学员作用域解析

学员解析由独立服务完成，而不是散落在 LangGraph 节点中：

- 唯一有效绑定：自动选择；
- 多个有效绑定：消息中唯一命中孩子姓名时选择，否则提示家长说明孩子姓名；
- 显式提交内部编号：先验证绑定，越权直接拒绝；
- 停用学员：不参与候选；
- 不存在、越权、失效绑定：统一安全提示，防止资源枚举。

解析结果在进入图之前写入受控状态，数据库工具与最终回答始终使用同一个 `effective_learner_id`。

## 4. 数据与展示边界

`learning_summary` 只组织已通过工具契约校验的字段：

- 剩余课时、累计消课；
- 出勤率、缺勤次数；
- 已发布阶段、完成度、优势、下一步重点。

内部学员编号、Token、服务地址、教师内部 `teacher_note` 均不进入家长回答。统计和阶段字段来自数据库/结构化主数据，不由 LLM 编造。

`report_history` 只产生固定动作：

```json
{
  "navigation_path": "/parent/reports",
  "navigation_label": "查看学情报告"
}
```

前端再次执行固定白名单校验。即使接口、模型或用户消息中出现外部 URL、`/admin` 或 `javascript:`，也不会渲染为可执行按钮。

## 5. 测试策略

- 意图专项：证明实时查询、历史查看、报告生成互不混淆，且不调用模型；
- 权限专项：覆盖唯一孩子、多孩子点名、多孩子未点名、无绑定、越权和停用学员；
- API 专项：证明阶段反馈来自数据库、不泄露内部备注，查看历史不新增 `ReportTask`；
- 前端专项：证明合法按钮可跳转，非法路径不显示；
- 回归与全量：覆盖多轮上下文、Redis 会话记忆、报告生成/下载和既有招生线索链路。

## 6. 报告周期的多轮补全

“生成学情报告”属于正确意图，但缺少必要的自然语言周期。系统不会默认猜测月份，
也不会要求家长填写后台表单式的开始日期和结束日期，而是先返回：

```text
请说明要生成哪个周期的学情报告，例如“本月”“上个月”或“最近30天”。
```

会话状态只保存受控的 `pending_intent=learning_report`。下一轮用户只回复
“最近30天”时，确定性周期解析器补全参数并恢复 `learning_report` 路由。非法日期、
冲突周期和无法解析的时间仍停留在澄清分支，不能进入报告任务和数据库工具。

澄清文本按照已确认的意图枚举选择固定模板，不调用 LLM 猜测缺失参数。这样既保持
自然对话体验，也保证生成 PDF、写入 MinIO 等有副作用动作只在参数完整后执行。
