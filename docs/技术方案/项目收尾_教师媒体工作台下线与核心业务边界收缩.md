# 项目收尾：教师媒体工作台下线与核心业务边界收缩

## 1. 决策背景

uPil 的核心价值已经收敛为四条可验证业务链路：

1. Supervisor 对家长和教师请求进行意图识别与受控路由；
2. FAQ/RAG 与结构化学情工具分别处理知识事实和动态业务事实；
3. 家长个人学情报告、教师班级学情报告生成单份 PDF，并通过私有对象存储交付；
4. 招生意向 Agent 在主回答旁路分析，高意向缺少联系方式时由固定规则主动询问，销售顾问老师领取线索并跟进。

教师媒体工作台包含素材上传、双人复核、图片读取、预签名地址、细粒度媒体权限和独立前端页面。它主要解决内容管理与后台审核问题，既不参与 Agent 路由，也不是学情报告或招生线索闭环的必要前置。继续保留会增加独立业务表、对象生命周期、审核状态机和后台页面，使产品逐渐扩张为通用教务或内容管理系统。

因此，本次不是因为功能无法实现而删除，而是主动收缩产品边界，把维护成本集中到多 Agent 主链路。

## 2. 下线范围

### 2.1 后端

- 删除媒体 Router 和 Presenter，不再注册 `/api/v1/media/*`；
- 删除 `MediaAsset` ORM 模型以及媒体请求/响应 Schema；
- 删除图片上传、读取、删除、预签名 URL 和双人复核逻辑；
- 删除媒体资源访问控制函数；
- 从应用装配、依赖注入、会话能力和前端 Bootstrap 中移除媒体入口；
- 认证权限白名单只保留当前仍使用的 `lead_followup`，历史 `media_upload`、`media_review` 即使残留在 Token 或数据库中也不会进入 `AccessContext`。

### 2.2 前端

- 删除 `/teacher/media` 路由和 `MediaWorkspaceView`；
- 删除媒体 API 客户端和类型；
- 删除导航、会话 Store 和功能开关中的媒体工作台能力；
- 重新执行前端构建并同步 FastAPI 静态资源，保证产物中不存在 `MediaWorkspaceView-*.js`。

### 2.3 配置与依赖

- 删除媒体桶、图片最大体积和图片预签名有效期等配置；
- 可选依赖从含义模糊的 `media` 更名为 `storage`；
- `MinioMediaStore` 保留历史兼容类名，但实现已经收缩为报告 PDF 专用。

## 3. 明确保留的能力

### 3.1 报告 PDF 私有交付

家长和教师学情报告仍使用统一链路：

```text
自然语言周期
  -> 后端确定性统计
  -> A2A 受控分析说明
  -> Markdown 内存中间态
  -> 固定模板 PDF
  -> 完整性校验
  -> MinIO 私有报告桶
  -> ReportArtifact 元数据
  -> FastAPI 重新鉴权并代理下载
```

这条链路直接完成家长和教师的业务交付，因此不能因为媒体工作台下线而一并删除。数据库只保存对象键、SHA-256、大小和页数；浏览器不会获得 MinIO 密钥、桶名、内部地址或可长期复用的预签名 URL。

### 3.2 RAGFlow 来源协议

`SourceReference.media_asset_id` 继续保留。它是 RAGFlow `image_id`/`img_id` 的兼容映射，用于表示“该检索片段关联了一个外部图片来源”，不是 uPil 本地 `MediaAsset` 主键。

保留该字段可以避免产品范围调整破坏外部来源协议；当前代码不会使用它读取本地 MinIO 对象，也不会据此生成图片下载地址。知识原件、OCR 和图片说明由 RAGFlow 自身基础设施管理，所以 RAGFlow Compose 中自己的 `MINIO_BUCKET` 不属于本次删除范围。

## 4. 数据库迁移

新增：

```text
infra/production/migrations/006_retire_teacher_media_workspace.sql
```

迁移执行两项确定性操作：

1. 删除 `user_permissions` 中的 `media_upload` 和 `media_review`；
2. 删除已经退出产品边界的 `media_assets` 表。

历史迁移 `003_add_media_review_separation.sql` 保持不可变。已经部署过的环境按 003、006 的迁移顺序得到最终状态；新环境也可以完整回放迁移历史。不能通过修改 003 来伪造从未存在过媒体能力，否则会破坏已部署环境的迁移一致性。

## 5. 为什么迁移不直接删除历史 MinIO 图片

数据库事务无法和 MinIO 对象删除形成可靠的单一 ACID 事务。若迁移先删对象后回滚数据库，或者先提交数据库后对象删除失败，都会产生不可逆的不一致。历史对象还可能受审计、合同、隐私删除和备份保留策略约束，不能只凭对象前缀批量清除。

因此迁移只删除业务授权和关系表；历史图片对象由运维单独执行：

1. 导出对象清单、大小、摘要和最近访问时间；
2. 对照数据库备份和业务保留策略确认归属；
3. 先转入隔离前缀或设置生命周期，再经过观察期删除；
4. 保存删除批次、操作者和异常对象记录。

## 6. 已退役 API 的 HTTP 语义

Vue SPA 挂载在根路径后，未注册的 POST API 原本可能由 `StaticFiles` 返回 405。对已经退役的媒体接口，这会让调用方误以为路径存在、只是方法不正确。

`SpaStaticFiles` 现在对所有落入静态层的 `/api/*` 请求统一返回 404：

- 已注册 API 仍由 FastAPI Router 正常处理；
- 未知或已退役 API 明确表示资源不存在；
- 非 API 的 Vue history 路由仍回退到 `index.html`；
- `/teacher/media` 不再加载旧页面，而是进入前端 NotFound。

## 7. 安全与兼容边界

- 历史媒体权限失败关闭，不从请求头、JWT 或数据库残留中恢复；
- 报告下载每次重新校验家长绑定关系或教师实际授课关系；
- 报告对象只允许固定 `reports/{task_id}/{sha256}.pdf` 键格式；
- PDF 在上传和下载边界复核魔数、摘要、大小、页数和任务元数据；
- `MinioMediaStore` 只为稳定导入路径保留旧类名，不代表媒体工作台仍存在；
- 不接真实 DSH，现有 `DisabledDSHConnector` 继续失败关闭。

## 8. 测试策略

专项测试覆盖：

- 报告桶按需创建且保持私有；
- PDF 上传、读取、连接释放、删除补偿和非法对象键拒绝；
- PDF 魔数、体积、SHA-256、文件名和任务 ID 校验；
- Session 与 Bootstrap 不再暴露媒体权限或功能开关；
- 数据库和 Token 中残留媒体权限也不会进入认证上下文；
- Seed 清理旧媒体权限并继续建立销售顾问最小权限；
- 迁移 006 删除旧权限和 `media_assets`；
- 历史 `/api/v1/media/*` 路径统一返回 404；
- 家长/教师报告接口和报告下载链路保持可用；
- 前端类型检查、组件测试、构建和后端静态资源同步。

专项基线为 `129 passed, 3 warnings`，integrations 相关回归为 `24 passed`，前端 typecheck、`12 passed`、普通构建和 `build:backend` 均通过。`compileall` 通过，Windows 后端最终全量为 `421 passed, 8 skipped, 3 warnings`。全量回归还发现统一 Seed 已创建 T1004，而旧线索测试夹具重复插入该稳定身份；修复夹具改为复用 Seed 身份后，招生线索专项 `21 passed`，业务实现未改动。

## 9. 发布与回滚边界

推荐发布顺序：

1. 备份 PostgreSQL，并盘点历史媒体对象；
2. 部署已移除媒体入口、且能容忍旧表短暂存在的新应用；
3. 执行迁移 006；
4. 验证媒体 API 为 404、媒体页面为 NotFound、报告链路正常；
5. 按独立运维方案处理历史图片对象。

如果未来业务重新需要机构素材管理，不应回滚 006 或恢复旧静态分包，而应重新确认产品范围、权限模型和数据保留要求，通过新的数据库迁移和独立模块重新引入。数据库备份只用于故障恢复，不用于绕过新的架构评审。

## 10. 结论

教师媒体工作台下线后，uPil 的边界更清楚：RAGFlow 管理知识原件，uPil 负责 Agent 编排、业务鉴权、结构化学情、报告交付和招生线索；MinIO 仅承担报告 PDF 私有对象存储。该调整减少了一套与核心业务无关的后台工作流，同时没有削弱家长和教师可感知的报告闭环。
