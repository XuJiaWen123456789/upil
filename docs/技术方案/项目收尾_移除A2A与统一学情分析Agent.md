# 项目收尾：移除 A2A/DSH 与统一学情分析 Agent

> 状态：当前生效方案。本文描述现行生产代码、配置和部署边界；阶段 13 的 A2A/DSH 文档仅保留为历史实验记录。

## 1. 决策结论

项目保留 LangGraph 多 Agent 编排，但移除 A2A/DSH 远程调用、独立学情子服务、服务令牌、跨进程任务协议和对应容器。个人学情摘要、家长报告和教师班级报告统一路由到 `learning_analysis_agent`，Agent 内部再按三个单职责处理器分派：

- 个人摘要处理器：组织已经授权的个人结构化快照，回答当前对话问题；
- 家长报告处理器：把学员周期快照组织成固定模板报告；
- 班级报告处理器：把数据库确定性计算的班级统计组织成固定模板报告。

这里的“统一”是统一权限入口、状态契约和报告执行边界，不是把三类业务逻辑重新堆进一个超大文件。Supervisor 仍负责意图识别和图路由，工具仍只执行确定性查询，Service 仍维护事务和幂等，处理器只负责各自领域的内容组织。

## 2. 为什么移除

阶段 13 已经验证了 A2A 风格任务的状态、Artifact、超时、重试、脱敏和跨进程故障边界，但当前项目的实际约束发生了变化：三个学情能力位于同一代码库和同一权限域，由同一团队维护；报告正文已经采用本地固定模板；统计事实必须在主数据库内确定性计算。此时远程协议没有带来独立部署、独立扩缩容、异构运行时或长任务调度收益。

继续保留 A2A 会额外维护 HTTP 子服务、服务发现、服务令牌、健康检查、远程状态映射、网络重试和两套测试夹具。它还会让报告链路看起来像跨团队平台，而实际业务并没有对应的运行需求。移除后，架构更容易部署、调试和审计，故障点也从网络调用收敛为本地事务和对象存储边界。

## 3. 现行学情分析链路

~~~text
用户消息
  -> Supervisor 识别意图并校验会话上下文
  -> learning_analysis_agent
  -> 个人摘要 / 家长报告 / 班级报告处理器
  -> 受控回答或固定 Markdown 中间态
  -> PDF 转换、pypdf 复核、MinIO 私有存储
  -> FastAPI 按当前绑定或授课关系鉴权下载
~~~

个人出勤、课时、完课率、缺勤 TOP5、低课时和缺失考勤等数据由受权限保护的 Tool/Service 从数据库计算。任何模板或文本组织处理器都不能重新计算或覆盖这些数字。报告 Markdown 只存在于当前请求内存中，不作为独立 Artifact 保存；新报告只保存一个 PDF Artifact。

## 4. 多 Agent 价值仍然成立

多 Agent 的价值在本项目中体现为职责隔离，而不是进程数量：

| 能力 | 独立职责 | 主要数据边界 |
| --- | --- | --- |
| Supervisor | 识别意图、维护会话上下文、选择业务路径 | 不直接编造学情事实 |
| FAQ Agent | 依据有来源的知识片段回答课程和校区问题 | 不读取学员私有数据 |
| 服务规则 Agent | 处理请假、调课、补课等规则边界 | 不承诺实时业务状态 |
| 学情分析 Agent | 统一承接三类学情分析请求并分派处理器 | 只消费已授权结构化数据 |
| 报课意向 Agent | 旁路识别试听/报名意向和联系方式授权状态 | 不回答用户、不越权改业务事实 |
| 人工转接节点 | 处理实时名额、争议和模型无法确认的请求 | 只创建受控转接结果 |

这种拆分可以让不同意图拥有独立 Prompt、工具白名单、测试和失败策略，同时避免为了“看起来像多 Agent”而把每个短流程强行部署成网络服务。

## 5. 报告执行与失败边界

家长和教师报告共用 `backend/app/services/report_execution.py`、`markdown_pdf.py`、MinIO 适配器、任务状态机和下载鉴权。统一流程为：解析自然语言周期，校验资源归属，确定性查询快照，调用对应报告处理器，校验固定字段，生成 PDF，复核 PDF，上传私有桶，再提交 Artifact 元数据。数据库提交失败时尽力删除已上传对象；失败任务不展示半成品，重新发起创建新尝试。

当前保留的 PDF 下载代理会在每次请求重新检查家长绑定或教师授课关系，浏览器不接触对象键、桶名、MinIO 地址或 Token。阶段 15-A-3 的 worker 租约、对象对账、保留期和补偿重试仍属于“生产增强，暂缓”，不能把当前同步执行描述成完整异步生产平台。

## 6. 何时重新评估 A2A

只有出现明确的独立运行需求才重新评估 A2A 或消息队列加内部 API，例如：学情分析由不同团队独立维护，需要单独扩缩容；出现分钟级长任务和跨服务调度；需要异构运行时或独立资源池；或者跨多个产品复用并且需要稳定的远程任务契约。届时应以容量、延迟、故障率和组织边界为依据，而不是以技术名词作为引入理由。

## 7. 验收边界

当前可验收的是本地 SQLite/适配器/Demo 身份下的业务闭环：LangGraph 路由、确定性学情统计、统一处理器、单 PDF、私有 MinIO 适配、动态鉴权、招生意向旁路和自动化测试。真实 OIDC、PostgreSQL、MinIO、RAGFlow、模型、机构教务数据和生产容量仍需按部署环境联调。历史 A2A/DSH 实验的通过记录不计入当前运行链路能力。
