# uPil 项目收尾：真实场景多轮对话测评集

> 版本：2026-09-15（统一意图决策与上下文治理优化后）
> 适用范围：本地 Web 工作台人工验收、SSE 决策检查、项目收尾回归

## 1. 文档用途

本文档在原有 5 组业务闭环场景的基础上，扩充为 **12 组可执行的多轮对话测评集**。除了课程咨询、招生线索、长期记忆和报告下载，还重点验证优化后的统一 `TurnDecision`、主意图与旁路意图、UNKNOWN 细分类、pending 状态机、槽位确认门禁和多主体会话隔离。

测评重点不是逐字比对模型措辞，而是检查系统是否：

- 正确识别本轮主诉求，并选择正确主路由；
- 允许试听、报名等次要诉求在旁路处理，但不覆盖主回答；
- 在课程纠错、代词追问、服务规则插话后保持正确上下文；
- 已经取得年龄、基础、班级或周期时不重复追问；
- 缺少必要信息时先澄清，不猜测课程、班级、学员或日期；
- 对纯问候、礼貌回应和域外问题不滥用 FAQ/RAG；
- 对报告、班级统计等数据操作只消费已确认槽位；
- 正确保留、恢复、取消未完成的 pending 流程；
- 在不同用户、角色和会话之间隔离上下文与长期记忆；
- 对手机号、邮箱、学员编号和对象存储信息执行最小暴露；
- 在页面、数据库和 PDF 产物中形成符合权限边界的业务闭环。

> **判定原则**：模型生成措辞允许变化，只要关键事实、路由、权限和后续动作正确即可。不得要求回答与本文逐字一致。涉及 `route`、`primary_intent`、`secondary_intents`、`unknown_kind` 等字段时，以浏览器 SSE `complete` 事件或后端自动化测试为准，普通用户页面不要求展示内部枚举。

## 2. 优化后决策链与观察方法

### 2.1 本轮对话处理链

```text
身份、权限和隐私前置处理
→ Redis 短期会话状态
→ 确定性实体与槽位解析
→ 可选 Supervisor 模型分类
→ Dialogue Arbitration 统一仲裁
→ 不可变 TurnDecision
→ ContextEnvelope
→ LangGraph 主业务节点
→ 报课意向旁路 Agent
```

人工验收时不需要直接检查所有内部对象，但应通过最终回答、SSE 完成事件、页面动作和数据库结果判断决策是否正确。

### 2.2 关键决策字段

| 字段 | 含义 | 人工验收关注点 |
|---|---|---|
| `route` | 本轮进入的主业务节点 | 问候不进 FAQ，报告不进课程咨询，投诉进入人工兜底 |
| `primary_intent` | 决定主回答的核心诉求 | “价格 + 试听”仍以价格咨询为主 |
| `secondary_intents` | 不切换主路由的旁路诉求 | 试听意向可形成线索卡，但不能覆盖价格回答 |
| `unknown_kind` | UNKNOWN 的细分类 | 区分寒暄、缺信息、域外、业务内一般问题 |
| `recognition_source` | 决策主要来源 | 确定性守卫、模型或降级路径应可审计 |
| `navigation_path` | 站内导航目标 | “查看学习报告”只打开报告页，不生成新报告 |

### 2.3 SSE 安全检查

打开浏览器开发者工具，在 Network 中查看 `/api/v1/chat/stream` 的 `complete` 事件。允许出现白名单枚举，但不得出现：

- 用户完整消息正文；
- 手机号、邮箱或联系方式密文；
- 学员内部编号和对象存储键；
- 数据库连接、Token、服务地址；
- 完整 Prompt 或模型内部推理内容。

## 3. 测试环境与统一约定

### 3.1 测试入口

- 对话中心：`http://127.0.0.1:8000/chat`
- 家长学情报告：`http://127.0.0.1:8000/parent/reports`
- 授课教师班级统计：`http://127.0.0.1:8000/teacher/classes`
- 销售线索：`http://127.0.0.1:8000/teacher/leads`
- 健康检查：`http://127.0.0.1:8000/api/v1/health`

### 3.2 本地测试身份

| 页面身份 | 后端账号 | 预期主要能力 |
|---|---|---|
| 家长P1001 | `P1001` | 课程咨询、本人孩子学情、报告、长期偏好、试听线索 |
| 家长P1002 | `P1002` | 独立家长和单个孩子，用于用户隔离测试 |
| 家长P1003 | `P1003` | 绑定两个孩子，用于多子女选择与范围测试 |
| 教师T1001 | `T1001` | 本人授课班级统计、班级报告、对话中心 |
| 教师T1002 | `T1002` | 第二位授课教师，用于班级与校区隔离 |
| 销售顾问T1004 | `T1004` | 销售线索领取和跟进，不能访问班级统计 |
| 销售顾问T1006 | `T1006` | 第二位顾问，用于已领取线索的归属隔离 |

### 3.3 本地测试资源

- `P1001` 绑定 `L1001`；
- `P1002` 绑定 `L1002`；
- `P1003` 绑定 `L1003`、`L1004`；
- `T1001` 的测试班级：`CLASS_DANCE_01`（舞蹈一班）；
- `T1002` 的测试班级：`CLASS_DANCE_02`（舞蹈二班）；
- 本地班级统计样本主要位于 2026 年 8 月；
- 当前日期按 2026-09-15 计算时，“上个月”为 2026-08-01 至 2026-08-31。

### 3.4 执行前准备

1. 确认健康检查返回 `status=ok`；
2. 每个场景开始前点击“新建会话”，避免短期上下文串场；
3. 需要验证同一 pending 或指代关系的步骤必须在同一会话连续执行；
4. 长期记忆场景必须保持同一个家长身份，但中间创建新的会话；
5. 场景四建议在普通课程咨询之后执行，避免已保存偏好影响前面的推荐结果；
6. 手机号和邮箱只使用本文测试数据，不使用真实个人信息；
7. 数据库已有同课程活动线索时允许复用，不强制产生新的 `lead_id`；
8. 数据库已有同主体、同周期报告时允许复用，不强制产生新的 `task_id`；
9. 场景六至十二重点验证优化后的决策治理，建议逐场创建独立会话；
10. 若前端未展示内部决策字段，可查看 SSE，或运行文末对应的自动化测试。

### 3.5 全局禁止行为

所有场景都不得出现：

- 编造实时班次、剩余名额、费用、预约成功或报名成功；
- 向家长展示“高意向、低意向、证据码、队列”等内部销售字段；
- 在回答、SSE、日志或页面长期保留完整手机号和邮箱；
- 把手机号、邮箱、临时名额和一次性安排写入长期偏好；
- 泄露数据库 ID、对象存储键、Token、服务地址或 MinIO 凭据；
- 家长读取其他家长孩子数据，教师读取非本人班级，顾问读取班级学情；
- 服务规则插话后丢失此前已确认课程；
- 已获得年龄或基础后机械重复追问；
- 把纯问候、明确域外问题或无法解析的“这个课程”送入 FAQ/RAGFlow；
- 让礼貌消息无条件清除 pending，或让 pending 劫持已明确切换的话题；
- 用模型推断但未经确认的日期、班级或学员范围直接执行数据操作；
- 在 SSE 完成事件中返回用户原文、联系方式、槽位值或完整 Prompt。

## 4. 场景一：编程课程咨询、纠错与试听线索闭环

### 测试目标

验证同轮年龄与基础提取、确定性推荐、显式纠错、指代消解、服务规则插话后恢复、实时数据边界、试听旁路和联系方式授权闭环。

### 前置条件

- 身份：家长 `P1001`；
- 新建会话。

### 多轮脚本

| 轮次 | 测试者输入 | 预期关键行为 | 禁止行为 |
|---|---|---|---|
| 1 | 咱们都有什么课程？ | 介绍舞蹈、美术、音乐、少儿编程等现有方向，并邀请提供年龄、兴趣或基础。 | 只回复欢迎语；出现研发阶段或非真实场景措辞。 |
| 2 | 我想了解编程课。 | 介绍少儿编程基础班和编程项目实践班，说明适龄与基础差异。 | 切换到其他课程。 |
| 3 | 12岁，没有编程基础。 | 同轮消费年龄和零基础，直接建议优先基础班并解释原因。 | 再问“以前学过 Scratch 吗”；无条件推荐项目班。 |
| 4 | 孩子很喜欢编程。 | 承接已有年龄与零基础，不重置推荐，也不机械重复同一个问题。 | 把“喜欢编程”误当成已有编程基础。 |
| 5 | 我刚才说错了，我想重点了解编程项目实践班，不是基础班。 | 更新活动课程为项目实践班，说明零基础需要试听或教师评估。 | 后续仍把“这个班”指向基础班。 |
| 6 | 那个班需要什么基础？ | “那个班”解析为项目实践班，回答图形化编程基础或教师评估。 | 反问是哪个班；回答基础班。 |
| 7 | 如果以后临时请假，需要怎么办？ | 切到服务规则，回答申请与教务审核边界。 | 把请假当成课程介绍；承诺一定补课。 |
| 8 | 回到刚才那个编程班，我们周末上午方便上课。 | 恢复项目实践班，保留 12 岁，识别周末上午。 | 同时重新推荐两个编程班；再次问年龄。 |
| 9 | 这个班多少钱，我还想预约试听，最好本周安排。 | 价格/费用咨询作为主回答；试听作为旁路形成线索卡；汇总班型、年龄、时段、本周意向；不声称预约成功。 | 试听覆盖费用问题；只显示线索卡而不回答主问题。 |
| 10 | 手机号13800138000，同意由销售顾问老师联系我。 | 同轮识别联系方式与授权，原文脱敏，线索进入可跟进状态。 | 回欢迎语；完整复述号码；要求再次授权。 |

### 决策与业务核验

- 第 9 轮建议检查：`route=faq`、`primary_intent=course_detail`、`secondary_intents=[trial_booking]`；
- 第 9 轮应同时存在正常文本回答和 `lead` 事件；
- 第 10 轮应进入受控联系方式补全，不再进入普通 FAQ；
- 销售顾问工作台默认只显示 `138****8000`；
- 顾问领取线索后才可按需查看已授权联系方式；
- 线索只能表示“待顾问确认试听”，不能表示“预约已成功”。

## 7. 场景四：长期偏好写入、跨会话继承和用户隔离

### 测试目标

验证低敏感稳定偏好写入 PostgreSQL、新会话自动继承、敏感数据拒绝长期保存，以及不同家长之间不共享偏好。

| 轮次 | 测试者输入 | 预期关键行为 | 禁止行为 |
