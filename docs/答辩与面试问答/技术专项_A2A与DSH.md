# 技术专项：A2A 协议与 DSH 编码执行智能体

## Q1【高频·必问】为什么采用 A2A 协议？

**答：** 先给结论：**A2A 对客服问答本身没有大提升，但对 DSH 这个高风险组件是真实必要**。

理由分三层：

1. **安全隔离**：DSH 要执行数据分析脚本，是全系统风险最高的组件，必须独立部署在沙箱环境。一旦跨服务，就必须有标准化调用协议——A2A 提供了任务封装、身份认证和结果追踪的完整结构。
2. **可审计**：A2A 的 Task + Artifact 让每个报表数字可追溯：什么参数、哪个模板版本、什么执行轨迹算出来的。未成年人数据场景这是刚需。
3. **可演进**：智能体服务化解耦后可独立扩容替换。FAQ 是 IO 密集、DSH 报表是 CPU 密集，扩缩容策略完全不同，必须分开部署才能分别伸缩。

**加分收尾：** "我们没有过度设计——延迟敏感的 FAQ 和学情查询仍走 LangGraph 进程内编排，只有计算密集的报表任务走 A2A 远程调用。"

## Q2【高频】A2A 和 MCP 有什么区别？为什么不用 MCP？

**答：** 一句话分界：**MCP 连接智能体和工具，A2A 连接智能体和智能体**。

- LangGraph 调 RAGFlow 检索：RAGFlow 是被动的检索工具，属 MCP 语义；
- Supervisor 调度 DSH：DSH 是自主的智能体服务，接收任务、自己决策执行、返回结果和轨迹，属 A2A 语义。

判断标准是**对方有没有自主性**：工具被调用即执行，智能体接收任务后会自行规划执行过程。

## Q3【高频·必问】为什么不让大模型自由写代码生成报表？

**答：** 这是我评估后主动否决的方案，三个理由：

1. **确定性丢失**：同一个月问两次完课率，模型两次生成的脚本可能不同，数字可能不一致。客服系统同一问题答案不同 = 失信。
2. **正确性风险**：模型生成的 SQL 可能漏 WHERE 条件，把别的班级学员算进缺勤 TOP5——跨班数据泄露。
3. **审计断裂**："这报表哪段代码算的"无法回答，因为没有经过测试的固定代码。

**修正方案——模板化执行：**

```
模型做：意图识别 + 参数提取（班级、时间范围、指标）
模型不做：写计算代码

DSH 内部：匹配预置模板（如 class_attendance_report）
         → 填参数到经过单元测试的参数化 SQL/Python
         → 沙箱执行
         → 返回报表 + 执行轨迹 Artifact
```

这体现核心原则：模型负责理解和表达，确定性代码负责计算。

## Q4 DSH 的失败兜底怎么设计？

**答：** 校验→重试→人工的三级链路：

1. Supervisor 对 DSH 返回做**数值边界校验**（完课率必须在 0~1）和**隐私扫描**（输出不得含手机号、身份证号）；
2. 校验失败自动重试 2 次（可能是瞬时故障或生成偏差）；
3. 两次仍失败，**确定性转人工**，不给模型自由发挥的机会。

答辩要点：降级路径是确定性代码写的，不依赖模型"自觉"。

---

## Q5 A2A Task 里为什么不传自由文本？

**答：** 输入是自由文本，模型可能从文本里"脑补"出越权参数（比如用户说"看看全校的"，模型就真传了全校范围）。所以 Supervisor 完成参数提取后，A2A Task 里只传**结构化参数 + 发起人身份**，DSH 端再做权限校验。两层校验：入口校验意图，出口校验范围。

---

## Q6 为什么 DSH 放在第 5 阶段而不是现在做？

**答：** 依赖关系决定：DSH 算的完课率、缺勤 TOP5 都来自班级、出勤、消课表——第 2 阶段才建数据模型。没有真实数据结构的报表智能体只能造假数据演示。但第 2 阶段会**预留** report_task 和 report_artifact 表，避免第 5 阶段回头改库。这是"架构先行、实现后置"的排期方法。

---

## Q7 一期没实现真 A2A 调用，答辩怎么说？

**答：** 主动说清楚边界："一期智能体节点已按 A2A Task 数据结构设计接口，但调用发生在进程内，因为跨服务调用的网络开销对秒级客服问答不划算。真正需要隔离的 DSH 在第 5 阶段落地时会独立部署为 A2A 服务，届时 Supervisor 主流程无需重构，因为接口早已对齐。"——**知道什么时候不用一个技术，比会用它更加分。**
