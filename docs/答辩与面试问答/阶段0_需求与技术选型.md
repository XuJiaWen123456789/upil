# 阶段 0：需求收敛与技术选型

## Q1【高频】为什么把原始需求缩小成"智能客服 + 课时学情助手"？

**答：** 原始需求同时覆盖客服、教务、教学、运营、销售五大模块，存在范围失控风险。我按三个标准收敛：

1. **闭环完整性**：选中的功能必须能形成"用户提问→路由→处理→返回"完整链路；
2. **数据依赖单一**：一期只依赖课时、消课、出勤三类结构化数据，不需要打通复杂教务系统；
3. **风险可控**：砍掉涉及资金（收费退费）、不可逆操作（自动改排课）和高合规风险（学员画像预测）的功能。

被砍掉的功能不是不做，而是依赖一期数据底座——没有课时出勤数据，续班提醒和运营看板都是空中楼阁。

---

## Q2【高频】为什么用 LangGraph 而不是让一个大 Prompt 处理所有请求？

**答：** 客服场景的核心矛盾是"不同请求需要完全不同的处理路径和权限"：

```
家长问课时余额 → 需要查数据库 + 校验绑定关系
家长问课程介绍 → 只需要 RAG 检索
家长投诉 → 必须转人工，不能让模型自由发挥
```

单一大 Prompt 有三个致命问题：权限判断和业务逻辑混在一起、无法单独测试各环节、失败时无法定位是哪个环节出错。LangGraph 的显式图结构让 Supervisor 节点、咨询节点、学情节点各自独立，每条边都可单测，转人工是确定性的图路径而不是模型的临场发挥。

## Q3 为什么 LangChain 和 LangGraph 要一起用？只用一个不行吗？

**答：** 职责不同：

- LangChain 是**能力库**：模型调用、Prompt 模板、结构化输出、Retriever 抽象；
- LangGraph 是**编排器**：状态机、条件路由、重试、人工兜底。

只用 LangChain 会退化为链式调用，无法表达"低置信度转人工"这种条件分支；只用 LangGraph 则要自己封装模型调用、流式输出解析等轮子。两者组合各取所长。

## Q4【高频】为什么对话接口用 SSE 而不是 WebSocket？

**答：** 本项目对话是"客户端提问→服务端流式回答"的**单向流**，SSE 完全够用且更简单：

| 维度 | SSE | WebSocket |
|---|---|---|
| 方向 | 服务端→客户端单向 | 双向 |
| 协议 | 纯 HTTP | 需协议升级 |
| 断线重连 | 浏览器自动 | 需自己实现 |
| 代理/防火墙友好 | 是 | 部分环境会被拦 |
| 语义匹配 | 单向流式回答 | 聊天室、协同编辑 |

如果未来做"人工客服实时打字对话"才需要 WebSocket，当前场景用它属于过度设计。

## Q5 为什么选 RAGFlow 而不是 pgvector？

**答：** 关键差异在**文档解析能力**：

教育机构的实际知识源是 Word 课程手册、PDF 招生简章、图片课表——这些需要版面分析、表格结构识别才能切出高质量片段。pgvector 只解决"存向量、算相似度"，解析要自己写，而解析质量直接决定检索质量。RAGFlow 内置深度文档理解，切分效果对非结构化教育资料更友好。

**取舍：** RAGFlow 是独立服务，部署重（Docker + 内存占用高）；pgvector 轻但解析弱。本项目知识源以非结构化文档为主，解析质量优先级高于部署轻量性。若机构知识源本来就是干净的 Markdown，pgvector 反而更合适。

**边界：** 明确不让 RAGFlow 查实时课时出勤——结构化业务查询走 PostgreSQL，两者职责严格分离。

## Q6 为什么不用 Deep Agents？

**答：** Deep Agents 的能力是长任务规划、虚拟文件系统、子智能体递归——适合"调研并写一份行业报告"这种小时级任务。本项目是秒级客服问答，需要的是**可控、可预测、低延迟**。引入自主规划等于引入不确定性：响应时间不可控、调用成本不可控、行为路径不可复现。客服场景宁可能力上限低一点，也要行为可预测。

---

## Q7 大模型在系统里的职责边界是什么？【必考】

**答：** 一句话原则：**模型负责理解和表达，不负责计算和决策**。

```
模型做：意图分类、参数提取、结果组织成自然语言
模型不做：算课时余额、算出勤率、判断权限、排序名单
```

原因：教育场景涉及计费和未成年人数据，数字必须确定性可复现。模型算 8.5 节课和 SQL 算 8.5 节课，审计意义完全不同。所有数值由 SQL/Python 在服务端计算，模型只拿到算好的结果去"说话"。

---

## Q8 项目一期明确不做哪些功能？为什么？

**答：** 自动收费退费（资金安全）、自动改排课考勤（不可逆操作）、学员能力预测（合规风险）、试听报名识别和续班提醒（属销售域，依赖 CRM 数据）。答辩时主动讲这些，体现的是产品判断力：知道做什么之前，先知道不做什么。
