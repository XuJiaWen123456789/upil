# 阶段 5B：结构化学情工具答辩与面试问答

## Q1：为什么要把学情数据定义成 Schema？

**答：** 学员资料、课时、出勤和阶段进度来自不同数据源，直接把 ORM 对象或任意字典交给模型会造成字段泄露和格式漂移。Pydantic Schema 明确了字段、类型和数值范围，能在进入智能体或 A2A 任务前完成校验，也让接口、单元测试和远程节点共享稳定契约。

## Q2：为什么出勤率不能让大模型自己计算？

**答：** 出勤率属于业务事实，必须使用统一口径计算。例如本项目将指定时间范围内的出勤记录作为分母，出勤记录作为分子，并单独统计缺勤和请假。大模型可以把结果解释成家长听得懂的话，但不能自由生成数字，否则无法审计，也无法保证同一问题每次结果一致。

## Q3：为什么阶段进度暂时用 JSON，而不是直接放进 PDF？

**答：** PDF 适合课程规则、教师介绍和机构服务等非结构化知识；阶段进度会按学员和日期变化，适合结构化存储和精确匹配。当前 JSON 是脱敏演示快照，后续会替换成教务系统或教学评价系统的只读接口，不能把动态学员数据上传到公开 FAQ 知识库。

## Q4：这四个工具和 A2A 的关系是什么？

**答：** 工具是学情分析智能体内部的最小能力边界，负责授权、查询和确定性计算；A2A 是未来跨服务传递分析任务和结果的通信协议。简单课时查询直接调用工具即可，只有长耗时、需要独立资源或需要沙箱的复杂分析，才将脱敏后的 Schema 快照封装为 A2A Task。

## Q5：如果家长把别人的学员编号传进来怎么办？

**答：** 查询不会先按编号读取数据，而是先基于 AccessContext 检查家长绑定关系。未绑定时所有工具统一返回空结果，API 对外统一返回“未找到可访问的学情数据”，避免通过错误差异推断学员是否存在。生产环境中的角色和用户编号必须来自 JWT 或网关注入，不能相信请求参数。

## Q6：阶段 5B 的完成标准是什么？

**答：** 不只是新增几个 JSON 文件，而是形成可验证闭环：有结构化契约、有受控工具、有确定性指标计算、有越权测试、有 API 序列化测试，并且旧 SSE 学情接口仍然通过回归测试。当前全量测试为 29 条通过；真实教务系统和容器服务联调属于后续阶段，不能把演示快照当作生产数据。
