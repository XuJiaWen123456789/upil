# 阶段 12-H-7 答辩与面试问答

## 问题：为什么要为服务规则单独创建 Assistant，而不是继续使用公开咨询 Assistant？

**回答：**公开咨询主要处理课程介绍、适龄建议、试听和校区信息；服务规则涉及请假、补课、调课、退费、安全和异常处置，风险等级更高、回答边界不同。单独创建 Assistant 并绑定独立知识库，可以实现知识域隔离，降低错误召回和越权回答的概率，也便于分别评估检索准确率、提示词和版本变更。

## 问题：真实联调中如何避免模型直接编造动态业务数据？

**回答：**在路由层先执行确定性高风险判断。剩余课时、出勤、实时名额、实时排课和具体退费金额等问题不允许由静态文档或模型猜测；当前已有真实数据工具的学情查询进入数据库分支，其他动态数据进入人工兜底。静态请假、补课和调课规则才交给服务规则 Assistant。

## 问题：为什么调课问题要加入确定性规则，而不能完全交给 LLM？

**回答：**“课程可以调到其他时间吗”属于固定业务意图，但自然语言表达较短，模型可能因缺少课程、校区或时间信息而误判为澄清。将“调到其他时间”“换个时间”等表达加入确定性守卫，可以保证稳定进入服务规则分支；如果用户进一步询问实时空位，仍会被实时数据规则拦截并转人工。

## 问题：如何证明这次不是只完成了代码，而是完成了真实联调？

**回答：**本次先通过 RAGFlow OpenAI 兼容接口直连验证 Assistant 可用，再重启 uPil API 使新配置生效，最后通过真实 HTTP SSE 接口验证六类请求。结果覆盖服务规则、动态学情、实时名额人工兜底和公开 FAQ 四条链路，并通过 71 passed、1 skipped 自动化回归测试。
