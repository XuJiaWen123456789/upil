# 阶段 13-A：A2A 与 DSH 最小协议设计答辩问答

## Q1：为什么本项目需要 A2A，而不是直接调用一个 Python 函数？

**答：** 本地函数适合进程内调用，但学情分析未来可能独立部署、单独扩缩容或由不同团队维护。A2A 将任务、状态、关联 ID 和 Artifact 变成跨进程契约，Supervisor 不需要知道子节点内部实现，也能统一处理超时、重试和审计。当前先设计边界，避免为展示协议而过度分布式化。

## Q2：为什么把第二个智能体定义为学情分析智能体？

**答：** 学情分析具有清晰的独立职责：基于已经授权的结构化快照做统计、趋势总结和学习建议；它与 FAQ 的静态知识问答不同，也与教务系统的事实查询不同。这个职责边界既能体现多智能体分工，也能避免让一个模型同时承担课程咨询、数据库查询和分析解释。

## Q3：DSH 能不能直接查询 PostgreSQL？

**答：** 不能。主系统先完成身份校验和最小数据查询，只将脱敏后的结构化快照发送给 DSH。远程节点没有生产数据库连接，既降低隐私泄露风险，也避免远程代码执行能力扩大数据库攻击面。

## Q4：A2A Task 中为什么要有 task_id 和 correlation_id 两个字段？

**答：** task_id 标识某一个远程任务；correlation_id 用来把任务关联回上游 HTTP 请求。一次用户请求可能包含多次任务或重试，所以二者不能混为一个字段。当前项目已有 request_id，后续可将它作为 correlation_id 的上游来源。

## Q5：为什么需要 Artifact，而不是只返回一段字符串？

**答：** 学情分析可能输出报告、图表或后续可审计的结果。Artifact 让产物拥有独立 ID、媒体类型和受控引用，便于校验、保存和权限控制；客服回答只引用经过验证的内容，不把远程节点的任意文件路径或原始执行结果直接暴露给用户。

## Q6：DSH 的核心亮点是什么？

**答：** DSH 适合承担受控的数据分析和脚本执行任务，但必须放在沙箱、只读数据和资源限制内。它的价值不是“让模型随意执行代码”，而是把统计、清洗和报告生成封装成可审计的专用能力；执行失败、超时或结果校验不通过时必须安全降级。

## Q7：什么时候不应该调用 A2A/DSH？

**答：** 普通课程 FAQ 直接使用 RAGFlow 更简单；安全事件应现场处置；订单退费、实时名额和责任认定必须依赖相应业务系统或人工。A2A 只用于适合异步、可拆分、只读且可验证的学情分析任务。

## Q8：如何防止 DSH 结果被当成真实业务结论？

**答：** 任务输入标明数据范围和时间窗口，结果经过指标、隐私和格式校验；对外话术明确“基于当前已授权数据的分析建议”，不承诺升学、获奖或业务审批结果。动态事实和责任判断仍由教务系统或人工确认。

## Q9：本阶段是否已经接入真实 DSH？

**答：** 尚未接入。本阶段完成的是可执行的最小协议、脱敏边界和故障策略。下一步先做本地 Mock A2A 子节点验证任务生命周期，再决定是否引入真实 DSH；这样可以先证明链路设计正确，不依赖外部账号和网络稳定性。
