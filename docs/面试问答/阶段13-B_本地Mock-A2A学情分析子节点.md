# 阶段 13-B 面试与答辩问答：本地 Mock A2A 学情分析子节点

> 当前 A2A 节点是本地协议原型，数据均为虚构演示数据，不能描述为已在真实机构生产运行。

## Q1：为什么不一开始就安装完整 A2A SDK 和 DeepSeekHarness？

**答：** 我先验证任务合同、脱敏字段、超时重试、Artifact 校验和失败兜底。如果直接引入网络服务、SDK 和代码执行环境，协议错误、网络故障和业务问题会混在一起。先做本地 Mock 可以低成本完成契约测试，再替换传输层，符合渐进式架构原则。

## Q2：本地 Mock 算不算真正使用了 A2A？

**答：** 当前不能宣称完成了真实跨服务 A2A 部署。它实现了 A2A 风格的任务、状态、Artifact、correlation ID 和失败语义，用于验证协议边界。接入独立服务后，才形成真正的网络 Agent-to-Agent 调用。

## Q3：A2A 对项目的业务价值是什么？

**答：** 价值不是增加技术名词，而是将耗时、可独立扩缩容的学情分析能力与客服主链路解耦。主系统负责身份、权限和可信数据查询，分析节点只接收脱敏快照并返回可审计 Artifact，实现能力独立演进、故障隔离、任务追踪和多实现替换。

## Q4：为什么远程节点不能直接连接数据库？

**答：** 远程 Agent 直连数据库会扩大权限面和数据泄漏面。主系统负责身份核验、授权和结构化查询，只把最小必要的脱敏快照传给分析节点，符合最小权限与数据最小化原则。

## Q5：如何避免把真实学员信息发送给远程节点？

**答：** 客户端将内部学员编号做 SHA-256 摘要，只传 learner_ref，不传姓名、手机号、身份证或完整聊天记录；协议模型使用 extra=forbid 拒绝未知身份字段，测试还断言 Artifact 不出现姓名和内部编号。

## Q6：为什么 request_id 要映射到 correlation_id？

**答：** request_id 追踪一次用户或 HTTP 请求，task_id 标识一次 A2A 任务。映射后可以跨 API、LangGraph、业务工具和远程节点关联同一链路，同时每次任务仍有独立 ID 可定位。

## Q7：为什么最多重试两次？

**答：** 有限重试可缓解瞬时超时，但无限重试会放大下游压力和用户等待。本项目只对明确的可恢复超时重试，最多两次；业务失败或 Artifact 校验失败不重试，直接安全降级。

## Q8：Artifact 为什么需要主系统再次校验？

**答：** 远程节点属于外部信任边界。主系统需要检查任务关联 ID、媒体类型、引用格式、产物数量、危险命令和本地路径，只有通过后才允许进入客服话术整理。

## Q9：当前 Mock 节点会执行代码吗？

**答：** 不会。它只接受严格的结构化学情输入，使用确定性模板生成 Markdown 摘要，不接收 command、SQL 或脚本字段，也不访问网络和文件系统。

## Q10：为什么第二个智能体是学情分析，而不是通用报表智能体？

**答：** 学情分析更贴合教育客服场景，可围绕出勤、课时进度和阶段反馈给出建议；通用报表范围过大，容易演变成任意代码执行平台。将能力限制为 learning_summary，既展示多智能体协作，又保留业务价值和安全边界。
