# 阶段 13-C 面试与答辩问答：LangGraph 与 A2A 编排

> 当前只完成本地 Mock A2A 接入，不能包装为已经在真实机构生产运行。

## Q1：LangGraph 和 A2A 各自负责什么？

**答：** LangGraph 负责主系统内部的意图路由、状态传递和业务流程控制；A2A 负责把已经授权、已经结构化的学情分析任务交给独立能力节点。两者不是替代关系，而是内部编排与跨 Agent 协作的分工。

## Q2：为什么先查数据库，再调用 A2A？

**答：** 真实课时和出勤属于动态事实，只能由有权限的业务系统提供。A2A 分析节点不负责身份鉴权和事实查询，它只分析主系统提供的可信脱敏快照。这样可以防止模型编造数据，也避免远程节点获得数据库权限。

## Q3：为什么使用功能开关？

**答：** A2A 是增强能力，不应该一次性替换稳定链路。功能开关便于灰度启用、快速回退和故障演练；关闭时保持原数据库摘要，开启时才增加分析 Artifact，这符合生产系统渐进发布思路。

## Q4：A2A 失败为什么还能返回结果？

**答：** 因为基础动态事实已经由数据库工具成功取得。A2A 只负责附加分析和建议，失败时可以降级为可信数据库摘要，而不是让整个客服请求失败。这体现了核心链路和增强链路的隔离。

## Q5：什么情况下不能降级为数据库摘要？

**答：** 如果身份校验失败、没有学员授权、数据库查询失败或结构化快照无法校验，就没有可信事实可返回，此时不会调用 A2A，也不能生成猜测答案，只能返回安全提示或转人工。

## Q6：SSE 为什么增加 a2a_task 事件？

**答：** A2A 任务可能比普通节点耗时长。独立状态事件能让前端展示“正在进行学情分析”，也能通过 task_id 和 correlation_id 做跨服务排障。但事件只暴露追踪字段，不暴露学员数据。

## Q7：如何证明链路可追踪？

**答：** HTTP 的 X-Request-ID 进入 LangGraph state，然后作为 A2A correlation_id。A2A 每次生成独立 task_id。自动化测试验证了响应中的 correlation_id 与请求头一致，从而可关联 HTTP 请求和下游分析任务。

## Q8：为什么成功时仍保留数据库摘要？

**答：** 数据库摘要提供可核验的动态事实，A2A Artifact 提供解释与建议。把两者分开可以清楚区分事实来源和分析来源，避免远程分析文本覆盖课时、出勤等确定性数据。

## Q9：当前方案距离真正 A2A 还缺什么？

**答：** 当前客户端和 Mock 节点仍在同一进程中。下一步需要独立 HTTP 子服务、标准能力描述、协议版本、服务鉴权、真实网络超时、任务持久化以及取消或异步查询。完成跨进程通信后，才能称为真正的远程 A2A 调用。

## Q10：如何向面试官说明这一阶段的工程含量？

**答：** 重点不是调用一个模型，而是完成受控编排：可信数据先行、最小化出站、功能开关、有限重试、Artifact 二次校验、SSE 状态传播和数据库降级。这些设计对应生产系统中的安全、稳定性和可观测性问题。
