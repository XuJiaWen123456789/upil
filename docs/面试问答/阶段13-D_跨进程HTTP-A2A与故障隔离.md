# 阶段 13-D 面试与答辩问答：跨进程 HTTP A2A 与故障隔离

> 项目口径：已完成本地跨进程 A2A 风格协议联调；尚未接入官方完整 A2A SDK、真实 DeepSeekHarness 或生产机构系统。

## Q1：阶段 13-D 相比 13-C 有什么实质提升？

**答：** 13-C 的客户端和 Mock Agent 在同一个 Python 进程，主要验证编排逻辑；13-D 将 Agent 拆成独立 FastAPI 服务，主系统通过真实 HTTP 调用，因而可以验证网络超时、服务认证、协议序列化、跨进程追踪和服务故障隔离。

## Q2：为什么不直接让 A2A 节点查询数据库？

**答：** 课时和出勤属于受权限保护的动态事实，必须由主系统完成身份、授权和数据查询。A2A 节点只接收脱敏后的最小快照，这既减少权限扩散，也避免子节点绕过业务规则或编造事实。

## Q3：如何保护学员隐私？

**答：** 主系统不会传输姓名、手机号和内部学员编号，而是对学员编号做 SHA-256 摘要并生成 learner_ref。协议模型拒绝未知字段，SSE 只返回 task_id、correlation_id 和状态，不返回完整快照或服务令牌。

## Q4：为什么 service token 还不够生产使用？

**答：** 它只能证明调用方持有共享秘密，不能解决传输加密、服务身份轮换、细粒度授权和密钥生命周期。生产环境需要 TLS/mTLS、Secret Manager、定期轮换、网关访问控制和审计。

## Q5：为什么只对 timeout 重试？

**答：** 超时可能是暂时性网络抖动，有限重试有恢复价值；401 表示认证错误、422 表示协议错误，盲目重试不会修复问题，还会放大流量。当前最多重试两次，避免重试风暴。

## Q6：如何避免 SSRF？

**答：** local_http 客户端只允许 HTTP 回环主机，拒绝局域网、公网、URL 凭据、查询参数和片段；请求协议没有 URL 字段，用户也不能指定目标地址。目标地址完全由服务端配置控制。

## Q7：远端返回 completed 就直接相信吗？

**答：** 不会。主系统会重新验证 Pydantic 协议、协议版本、task_id、correlation_id、Artifact 数量、媒体类型、引用格式和危险内容。远端节点不能自行决定其结果可信。

## Q8：A2A 服务宕机为什么不影响基础课时查询？

**答：** 系统将动态事实链路和分析增强链路分离。数据库工具先产生可信摘要，A2A 仅附加分析建议；A2A 超时、非 2xx 或结果非法时，LangGraph 回退到数据库摘要，并在 SSE 中标记失败状态。

## Q9：如何实现跨服务追踪？

**答：** 主 API 中间件生成或接收 X-Request-ID，LangGraph 将它作为 correlation_id 传给 A2A；每个任务另有唯一 task_id。这样可以按 correlation_id 串联用户请求，按 task_id 定位具体子任务。

## Q10：为什么本阶段不直接接 DeepSeekHarness？

**答：** 先用确定性 Mock 把网络、协议、鉴权、超时、结果校验和降级机制验证稳定，可以把基础设施问题与模型执行问题分离。直接接入代码执行框架会同时引入沙箱、资源配额和供应链风险，不利于定位问题。

## Q11：现在能说已经采用 A2A 协议了吗？

**答：** 严谨说法是“实现了版本化的 A2A 风格任务协议，并完成本地跨进程 HTTP 联调”。在没有对照官方 A2A 规范完成 Agent Card、任务生命周期和 SDK 兼容验证前，不应声称完整实现了官方 A2A 协议。

## Q12：下一步怎样进一步接近生产？

**答：** 增加任务幂等键和状态持久化、熔断与退避、结构化指标、分布式追踪、TLS/mTLS、密钥管理、资源配额和混沌测试；完成这些基础能力后，再用受控 DSH 执行器替换 Mock 分析器。
