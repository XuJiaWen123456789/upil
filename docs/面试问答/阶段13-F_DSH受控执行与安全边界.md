# 阶段 13-F：DSH 受控执行与安全边界答辩问答

## 1. 为什么不直接把 DeepSeekHarness 接到客服接口？

因为 DSH 可能具备生成或执行分析代码的能力，风险高于普通问答模型。客服接口还涉及
学员数据、权限、文件和业务系统，直接接入会造成越权、数据泄露和任意代码执行风险。
本阶段先完成任务契约、白名单门禁和故障关闭策略，再评估真实执行器。

## 2. DSH 在本项目里解决什么问题？

它适合承担结构化数据上的复杂学情分析，例如从出勤、完成课时和阶段记录中生成可读
的分析摘要。它不是所有客服问题的默认模型，也不替代 RAGFlow 的公开规则问答和
业务工具的动态事实查询。

## 3. 为什么第二个智能体仍然是学情分析智能体，而不是报表智能体？

学情分析与本项目的核心价值更一致：家长和教师关心学习过程、出勤和阶段反馈。报表
生成偏向运营后台，范围更大，还会引入更多数据导出和文件生成风险。因此当前把 DSH
限制在只读学情分析，报表能力留作后续独立扩展。

## 4. A2A 和 DSH 是什么关系？

A2A 负责标准化任务协作和结果回传，DSH 是可能被调用的执行器。A2A 规定 task_id、
correlation_id、约束、状态和 Artifact 等边界；DSH 负责在这些边界内执行被批准的
分析任务。两者解耦后，可以替换 DSH 实现而不改动 LangGraph 上层路由。

## 5. 当前是否已经接入真实 DSH？

没有。当前完成的是 DSH 适配器边界和安全门禁，`DisabledDshHarness` 会在验证通过后
明确返回未配置，并要求兜底，不会伪造成功。现有可运行链路仍是确定性 Mock 或本地
HTTP Mock A2A 子服务。

## 6. 如何防止 DSH 执行任意代码？

第一层是严格协议和技能白名单，只允许 `learning_summary`；第二层是强制禁止外部网络
和副作用；第三层是主系统只传脱敏结构化学情快照；第四层是未来沙箱需要限制文件、
进程、资源和依赖；第五层是结果返回后由主系统再次校验 Artifact 和隐私内容。

## 7. 为什么执行计划不携带 learner_ref？

执行计划是调度元数据，日志或下游编排只需要知道任务 ID、技能、超时和输出格式。
learner_ref 仍属于任务输入，不应扩散到计划、指标和普通日志中，这是数据最小化。

## 8. 如果 DSH 不可用怎么办？

采用 fail-closed：不把未执行或未校验的结果返回给用户，不进行无限重试，并设置
`handoff_required=true`。在主系统已具备可信数据库摘要时，可以回退到数据库事实；
如果没有可信结果，则转人工。

## 9. 这个阶段的亮点怎么说？

> 项目没有为了使用 DSH 而开放任意代码执行，而是把它封装成可替换的 A2A 执行器，
> 通过技能白名单、数据最小化、无网络/无副作用约束和结果二次校验控制风险。当前
> 先用默认关闭适配器验证 fail-closed 语义，未来满足沙箱和服务身份条件后再接入真实
> Harness。
