# 阶段 13-I-4：客服演示页与 SSE 可观测性问答

## Q1【高频】为什么不用原生 EventSource？

答：原生 EventSource 主要支持 GET，而本项目需要 POST 提交 JSON 请求体，所以采用 fetch 加 response.body.getReader() 消费 SSE。这样既保留 SSE 的服务端单向推送能力，也支持会话 ID、调试字段和请求取消。

## Q2【高频】SSE 和 WebSocket 如何取舍？

答：当前主要是服务端向浏览器单向推送回答片段，SSE 的实现和运维成本较低，适合 HTTP 基础设施。用户的新问题通过 POST 提交。只有需要高频双向通信时才考虑 WebSocket。

## Q3【高频】为什么设计 accepted、routed、a2a_task、complete？

答：一次请求包含接收、路由、Agent 执行、业务查询或 A2A 调用和回答生成。结构化事件可以展示进度、定位慢请求和区分路由错误、模型错误、数据库错误及子服务错误。complete 还是完整结束的可靠信号。

## Q4【高频】如何处理 SSE 网络拆包？

答：不能把一次 reader.read() 当作一个完整事件。前端维护 buffer，按空行拆分事件块，不完整尾部保留到下一次读取；TextDecoder 使用流式模式处理 UTF-8 跨包；结束时再 flush，并兼容 CRLF 和多行 data。

## Q5【高频】为什么隔离普通模式和答辩调试模式？

答：家长不需要看到内部文档、切片、A2A 任务 ID 或原始业务字段。调试模式用于答辩证明链路经过哪个 Agent 和供应商，但它只是展示能力，后端认证和授权仍是最终安全边界。

## Q6【高频】演示学员编号为什么只在调试模式出现？

答：它只用于本地触发 L1001 的结构化学情和 A2A 链路。正式环境应由登录态、JWT、网关或后端会话解析用户身份，并由服务端校验家长与学员的绑定关系，不能相信浏览器直接提交的身份字段。

## Q7【高频】A2A 子服务故障时怎么办？

答：主 API 先完成权限校验并取得可信数据库摘要，A2A 只负责分析增强。子服务超时或失败时保留数据库摘要、记录失败状态和关联 ID，不能为了生成完整答案而编造数据。

## Q8【高频】为什么普通模式的 sources 为空？

答：后端仍接收和归一化 RAGFlow 的真实引用，但家长端默认关闭来源暴露，避免泄露内部文档结构。调试模式可展示后端真实返回的来源，来源展示不等于把内部知识库直接开放给用户。

## Q9【高频】如何证明页面不是写死的 Demo？

答：FAQ 请求实际返回 provider=ragflow，学情请求实际出现 a2a_task=completed 且 provider=a2a_http；两个容器健康，自动化测试为 152 passed、1 skipped。页面只是展示层，后端链路和测试才是能力证明。

## Q10【高频】当前还没有做到什么？

答：当前仍是本地 staging 生产化约束原型，尚未接入真实机构认证、教务、订单、工单系统、Redis 集群和正式 DeepSeekHarness 执行器；A2A 节点仍为受控 Mock，业务资料和学员数据也是虚构演示数据。

## Q11【高频】下一步如何生产化？

答：补充可信认证上下文、Redis 或 PostgreSQL 会话、request_id/trace_id 指标、日志脱敏、RAGFlow 和 A2A 的超时熔断重试告警，并通过真实流量压测验证容量和故障恢复。
