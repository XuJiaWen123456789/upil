# 阶段 14-A-6：学情报告编排答辩问答

> 本文用于项目答辩和面试准备。当前项目是使用虚构数据的本地 staging 生产化约束原型；已验证 A2A Mock/HTTP 链路，但尚未接入真实 DeepSeekHarness。

## 1. 家长生成学情报告的完整链路是什么？

**答：** 请求先由 Supervisor 识别为 `learning_report`，主服务校验家长身份和学员绑定关系，再解析统计周期并从结构化业务数据库读取课时、出勤和已发布学习进度。主服务完成确定性统计和脱敏后创建 ReportTask，将匿名聚合快照通过 A2A 交给学情分析子节点。子节点只负责组织 Markdown 报告，主服务随后校验状态、质量和 Artifact，落库后通过 SSE 返回。

## 2. 为什么不让大模型或远程 Agent 直接查询数据库并计算出勤率？

**答：** 课时和出勤是高可信动态事实，直接交给模型会引入越权、SQL 风险和数字幻觉。项目把权限校验、数据库读取、日期边界和指标计算固定在主服务中，模型或远程 Agent 只能消费已脱敏的聚合结果。这种设计把“事实计算”和“语言组织”分开，便于审计和测试。

## 3. A2A 在学情报告场景中的实际价值是什么？

**答：** A2A 将客服主链路与报告执行节点解耦。主服务只依赖稳定的任务、状态、质量和 Artifact 合同，不依赖子节点内部使用何种模型或执行框架；报告节点可以独立部署、限流、超时、重试和替换。对于比普通 FAQ 更耗时的报告任务，这也为后续异步执行、取消、进度查询和跨团队维护提供统一边界。

## 4. 主系统 ReportTask ID 为什么不能和 A2A task_id 混用？

**答：** ReportTask 表示业务系统中的报告申请及审计记录，A2A task_id 表示某次远程执行任务。一次业务任务未来可能因重试、迁移或换节点对应多次远程执行，因此两者必须分离。这样既能保持业务幂等，又能追踪具体执行链路。

## 5. 如何保证重复请求不会重复生成报告？

**答：** 主服务使用请求 ID、请求人、匿名学员引用和报告周期生成不包含原始业务主键的幂等任务 ID。相同请求参数再次到达时复用已有任务；若任务已经完成，则直接返回持久化 Artifact，不再次调用 A2A。相同 ID 对应不同参数时拒绝覆盖。

## 6. 如何防止报告泄露学员隐私？

**答：** 主服务在 A2A 调用前去除姓名、原始 learner_id、联系方式、教师内部备注和原始出勤明细，只发送匿名引用与聚合指标。任务 scope 也不保存原始 learner_id。返回阶段再次检查正文不能出现原始 ID 或匿名引用，SSE 任务事件仅展示任务状态和追踪 ID。

## 7. 为什么 Artifact 不能直接保存远程节点返回的任何内容？

**答：** 远程节点仍属于不可信边界。主服务要求任务成功、质量门禁通过、只返回一个 `learning-report.md`，并使用统一 `A2AArtifact` 合同拒绝脚本、Shell 命令、本地路径和超大正文；合法正文再计算 SHA-256 后持久化。这样可以避免把代码执行结果或内部路径误当成家长报告。

## 8. A2A 或报告节点失败时系统如何处理？

**答：** 主任务进入 failed 终态，用户只看到统一的安全失败提示，不会看到远程响应正文、异常堆栈、服务地址、Token 或数据库细节。报告场景不会回退为模型猜测的报告；必要时提示稍后重试或转人工。

## 9. 当前是否已经使用真实 DeepSeekHarness？

**答：** 还没有。当前完成的是 DSH 执行边界设计、A2A 报告合同、脱敏快照、任务状态和 Artifact 门禁，并通过本地受控 Mock 与 HTTP 子服务验证跨服务链路。真实 DSH 接入仍需确认官方运行时、沙箱策略、部署方式和协议适配，不能在简历或答辩中表述为已完成。

## 10. 如何证明这条链路不是 PPT 架构？

**答：** 项目有函数级、持久化层和 API/SSE 端到端测试。测试验证了家长权限、报告周期、数据库统计、A2A 调用、任务幂等、Artifact 落库、非法产物拒绝、服务禁用降级和隐私字段隔离。本阶段全量回归为 194 passed、1 skipped。
