# 阶段 14-B 面试问答：生产认证与统一授权

## Q1：为什么不能直接信任 `actor_role` 和 `actor_user_id`？

**答：** 它们来自客户端，请求者可以任意修改。如果业务层据此创建管理员身份，会形成直接
的权限提升。项目只在 `demo` 模式保留它们用于联调；可信模式完全忽略这些字段。

## Q2：Trusted Headers 等同于 JWT 吗？

**答：** 不等同。JWT 是可独立验签、带有效期和声明的令牌；Trusted Headers 是认证代理
完成登录后向内网服务传递身份的一种方式。它成立的前提是 API 不能被外部绕过代理直连。

## Q3：如何防止攻击者自己构造认证 Header？

**答：** 代理先删除外部同名 Header，再注入认证结果；API 只允许代理网络访问，并验证内部
共享密钥。生产还应使用 TLS，跨主机场景可增加 mTLS，并定期轮换共享密钥。

## Q4：既然代理已经给出角色，为什么还要回查数据库？

**答：** 数据库是应用当前账号状态和权限范围的权威来源。回查可以即时识别停用账号、角色
变化和校区范围，并防止过期或错误的代理声明直接扩大业务权限。

## Q5：认证和授权有什么区别？

**答：** 认证确认用户身份，授权判断该身份能否访问具体资源。项目先生成 `AccessContext`，
再通过家长绑定、教师授课关系和管理员校区范围判断学员、班级和媒体权限。

## Q6：为什么越权查询学员或班级返回 404，而有些操作返回 403？

**答：** 对可枚举资源统一返回 404，可以隐藏资源是否存在；媒体上传等动作不会暴露某个目标
资源的存在性，返回 403 更能表达“身份有效但无该动作权限”。

## Q7：身份数据库故障时为什么不能降级到 Demo？

**答：** 降级会把依赖故障变成鉴权绕过。可信模式无法确认账号状态和权限范围时必须失败
关闭并返回脱敏 503，由监控告警和运维恢复身份库。

## Q8：为什么教师或管理员缺少校区配置时返回 503？

**答：** 当前权限模型以校区约束职员访问范围。空校区如果被解释成全局权限，数据漏填就会
造成横向越权，所以它属于服务端权限配置错误。集团管理员应通过显式角色或权限表表达。

## Q9：如何从 Trusted Headers 迁移到 OIDC/JWT？

**答：** 在 HTTP 边界新增 JWT 验签适配器，校验 issuer、audience、签名、过期时间和必要
声明，再回查本地权限并生成同一个 `AccessContext`。业务授权层和 LangGraph 不需要改变。

## Q10：当前能否说项目已具备生产登录能力？

**答：** 不能。当前完成的是认证代理后的应用侧认证与授权边界，尚未实现真实身份提供方、
登录页面、令牌生命周期、MFA 和代理部署。准确表述应是“完成可替换的生产认证适配层”。
