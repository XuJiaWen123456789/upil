# 阶段 15-A-1：报告所有权与安全下载面试问答

## Q1：为什么报告不能只在 SSE 中返回正文？

**答：** SSE 适合反馈当前请求进度，但连接断开后不便于恢复，也不能自然支持历史列表、状态查询和重复下载。项目把报告建模为持久化任务资源，SSE 只返回主系统任务编号，后续查询和下载都重新执行认证与所有权校验。

## Q2：主系统 report_task_id 和远程 A2A task_id 有什么区别？

**答：** A2A Task ID 描述远程执行节点的一次任务生命周期，用于跨智能体追踪；`report_task_id` 描述 uPil 内部受权限保护的业务资源，用于所有权、状态、Artifact 和审计。远程节点可以替换，但主系统资源编号和权限语义必须保持稳定。

## Q3：如何防止家长读取其他家长的报告？

**答：** 查询条件同时包含 `task_id`、认证上下文中的 `requester_id` 和固定 `task_type`，所有权直接在 SQL 层过滤。请求参数中的模拟用户只在 Demo 模式有效，OIDC 或可信 Header 模式完全忽略它。

## Q4：为什么越权访问也返回 404，而不是 403？

**答：** 对单个资源返回 403 会确认这个任务真实存在，攻击者可以枚举任务编号。项目将不存在、类型不匹配和属于其他家长统一处理为 404；教师访问整个家长报告能力时则返回 403，因为这是角色能力边界，不涉及确认某个资源的所有者。

## Q5：为什么 completed 状态还不能直接下载？

**答：** 状态和产物可能因历史迁移、人工修改或跨系统部分失败而不一致。下载前还需检查 Artifact 数量、类型、非空正文、SHA-256、A2A 内容契约和内部引用，避免把脏数据或危险内容直接暴露给家长。

## Q6：SHA-256 在这里解决什么问题？

**答：** 它用于发现报告正文落库后是否发生非预期变化，并支持幂等比对，不用于证明作者身份，也不是加密。若需要抵抗有数据库写权限的攻击者同时篡改正文和摘要，应增加 KMS 管理的 HMAC 或数字签名。

## Q7：为什么使用 hmac.compare_digest 比较摘要？

**答：** 普通字符串比较可能在首个不同字符处提前结束。恒定时间比较是一项低成本的安全习惯，可以减少基于比较耗时推断摘要前缀的侧信道。这里真正的核心仍是服务端重算摘要和严格的访问控制。

## Q8：报告详情为什么不直接返回 Markdown 正文？

**答：** 列表和详情属于高频元数据接口，不应批量加载或传播敏感正文。正文只能通过独立下载边界获得，这样可以集中执行完整性校验、设置缓存策略并记录下载审计。

## Q9：下载接口为什么使用 private, no-store？

**答：** 学情报告包含个人教育数据，不应被共享缓存、代理或浏览器长期保存为可复用缓存条目。`private, no-store` 降低中间缓存和本地缓存造成的数据残留风险，但不能替代终端设备安全和传输层 TLS。

## Q10：下载审计为什么不记录正文和 checksum？

**答：** 审计目标是回答谁在何时访问了哪个资源以及结果如何，不需要复制报告内容。把正文或内部引用写入日志会让敏感数据扩散到日志平台、告警系统和更多运维账号。

## Q11：为什么审计写入失败时不继续下载？

**答：** 学情报告属于受保护资源，生产要求下载行为可追溯。项目采用失败关闭，审计事务失败返回 503，不形成“文件已经发出但系统没有访问记录”的窗口。更高吞吐场景可使用事务 outbox 和可靠异步审计，但不能简单忽略失败。

## Q12：当前方案是否已经适合大规模异步报告？

**答：** 还不适合。当前任务已持久化并有状态机，但 A2A 生成仍在请求链路同步等待。大规模生产需要消息队列、worker 租约、心跳、超时回收、重试退避、幂等消费和死信处理。

## Q13：为什么下一步先做 PDF 和 MinIO？

**答：** 家长需要稳定、可打印且版式一致的交付物。PDF 比 Markdown 更适合作为正式报告；大文件不应长期放在关系数据库。下一阶段会用受控模板生成 PDF，验证中文字体与分页，将文件保存到私有 MinIO，并通过短时授权下载。

## Q14：简历中如何准确描述这项工作？

**答：** 可以写：

> 设计家长学情报告资源闭环，将 LangGraph/A2A 生成结果持久化为有限状态任务，通过 SQL 所有权过滤、防枚举 404、Artifact SHA-256 与内容契约复核、最小化响应和下载审计实现授权查询与安全交付。
