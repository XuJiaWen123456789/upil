# 项目收尾面试问答：为什么下线教师媒体工作台

## Q1：已经实现的教师媒体工作台为什么还要下线？

**答：** 功能是否保留不能只看开发成本是否已经投入，还要看它是否强化产品主线。uPil 的主线是多 Agent 咨询、结构化学情、报告交付和招生意向旁路；媒体上传、双人复核与图片访问主要属于内容管理后台。继续扩展会引入独立权限、审核状态机、对象生命周期和后台页面，使系统偏离核心闭环。因此下线是产品边界决策，不是因为技术上无法完成。

## Q2：这是不是删除了项目中所有 MinIO 能力？

**答：** 不是。删除的是图片上传、审核、读取和预签名访问；MinIO 继续保存家长和教师学情报告 PDF。报告对象使用私有桶，浏览器通过 FastAPI 下载，后端每次重新鉴权并复核对象完整性。报告 PDF 是用户最终可获得的业务产物，和媒体后台的价值不同。

## Q3：为什么还保留 `MinioMediaStore` 这个类名？

**答：** 它是报告服务和既有调用方使用的稳定导入符号。当前类已经只实现报告 PDF 方法，保留名称可以减少一次与业务无关的破坏性迁移。代码注释和文档明确说明这是历史兼容类名；后续如果要更名，应先提供新类名、迁移生产导入，再删除兼容别名，而不是同时改动存储行为和所有调用方。

## Q4：删除 `MediaAsset` 后，为什么 `SourceReference.media_asset_id` 还存在？

**答：** 两者已经没有数据库主外键关系。`media_asset_id` 是 RAGFlow 返回的 `image_id`/`img_id` 的外部来源协议字段，用于保留检索来源可追溯性。uPil 不会用它读取本地图片或生成下载地址。保留协议字段可以避免内部产品收缩破坏外部适配器契约。

## Q5：为什么不连 RAGFlow Compose 中的 MinIO 桶一起删除？

**答：** RAGFlow 自己需要对象存储管理知识原件，这是外部检索基础设施的内部职责；uPil 下线的是自身教师媒体工作台。两套桶属于不同系统边界。删除 RAGFlow 的存储配置会破坏知识解析和检索，与本次产品收缩无关。

## Q6：迁移 006 为什么删除数据库表，却不删除 MinIO 中的历史图片？

**答：** PostgreSQL 事务和 MinIO 删除无法组成可靠的跨系统事务，而且历史图片可能有审计、隐私、合同和备份保留要求。迁移只清理旧权限和 `media_assets` 关系表；对象由运维先盘点，再按隔离、观察期、生命周期和审计记录独立处理，避免不可逆误删。

## Q7：为什么保留历史迁移 003 和历史阶段文档？

**答：** 已发布迁移必须不可变，否则旧环境和新环境回放会得到不同结构。003 记录能力曾经如何建立，006 记录它如何退出。历史阶段文档也用于说明当时的设计和后来的取舍，但顶部明确标注为历史方案，不代表当前仍可用。这样的决策轨迹比直接抹掉历史更利于审计和团队续接。

## Q8：为什么已退役 API 要返回 404，而不是 403、405 或 410？

**答：** 当前版本已经不再注册这些资源，404 最符合“接口不存在”的现状，也避免向未授权调用方额外暴露历史资源信息。405 容易让调用方误以为路径仍存在，只是方法不正确；403 则暗示接口仍可用但权限不足。410 在公开、长期版本化 API 中可以考虑，但当前内部 API 没有为退役状态建立独立契约，因此统一 404 更简单一致。

## Q9：如何证明媒体下线没有破坏报告功能？

**答：** 存储专项不再测试图片，而是覆盖报告私有桶、固定对象键、PDF 魔数、SHA-256、大小、文件名、任务 ID、读取连接释放和删除补偿；API 回归继续覆盖家长/教师生成、列表、详情和鉴权下载；前端重新构建后确认没有媒体分包。媒体退役专项为 `129 passed`，integrations 为 `24 passed`，Windows 后端全量为 `421 passed, 8 skipped, 3 warnings`，`compileall` 也通过。

## Q10：如果未来又需要素材管理，是否直接恢复旧代码？

**答：** 不建议。首先要重新确认素材来源、授权、隐私删除、审核职责、对象保留和与 RAGFlow 的边界，再通过新模块和新迁移引入。直接恢复旧代码会把已经改变的认证、前端和数据结构一起带回，也无法证明符合新的业务与合规要求。旧实现可以作为设计参考，但不能当作无条件回滚包。

## Q11：这次收缩对多 Agent 项目的价值是什么？

**答：** 它减少了与 Agent 无直接关系的后台能力，使目录、权限和运维资源围绕四个核心域展开：对话路由、知识/学情工具、报告任务和招生线索。项目不再靠功能数量证明复杂度，而是用 Agent 边界、确定性事实、权限失败关闭、异步产物和旁路分析形成完整业务闭环。
