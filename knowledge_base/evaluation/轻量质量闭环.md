# 知识问答轻量质量闭环

本项目用人工审核的 30 条虚构场景（课程/校区 15 条，服务规则 15 条）验证 RAGFlow Chat 回答及文档引用。此项评测不覆盖 Supervisor 的多轮状态、身份权限或学情 SQL；这几类已有独立测试。

## 使用

```powershell
& ./.venv/Scripts/python.exe -m scripts.evaluate_knowledge
& ./.venv/Scripts/python.exe -m scripts.evaluate_knowledge --live --output data/runtime-checks/knowledge-baseline.json
& ./.venv/Scripts/python.exe -m scripts.knowledge_evaluation.triage data/runtime-checks/knowledge-baseline.json --output data/runtime-checks/knowledge-triage.json
& ./.venv/Scripts/python.exe -m scripts.knowledge_evaluation.compare data/runtime-checks/knowledge-baseline.json data/runtime-checks/knowledge-after.json
```

默认命令仅检查样本格式，不访问外部服务；--live 需要双 Assistant、Embedding/模型服务及 RAGFlow 均可用。任一题因服务不可用无结果则立即退出，不生成质量基线。非零退出码表示质量失败或环境不可用；控制台和输出文件只包含样本编号、指标及受控原因码。

指标中 keyword_proxy_pass 仅表示关键词和禁止语句的机械校验通过数；citation_hit 是期望文档是否出现在回答引用中，并非原始候选切片的 Recall@k，也不保证引用支撑了答案。答案正确性、拒答误伤和证据充分性仍需人工核查。每个问题的 boundary 标注用于人工归因，不会被简单关键字评分当成端到端状态机测试。

## 审核与回归

1. 人工从失败编号定位合成样本，核对回答与 RAGFlow 引用。真实会话不得自动复制到测试集或知识库，必须先取得授权并脱敏。
2. 在 triage 清单中将 cause 从 unreviewed 改为 knowledge_gap、retrieval、routing、generation、live_boundary 或 mechanical_proxy_false_positive，填写简短理由、修复动作与回归状态；不自动上传知识。仅引用文档名命中不能证明具体断言得到支撑，需要人工核对引用片段。
3. 先处理知识域选择、文档版本/缺失和明显的错误承诺；调整切片/检索配置后，以同一套样本与同一环境重跑，比较前后指标并抽样人工复核。
4. RAGFlow Chat API 的文档引用无法计算真实 Recall@k/MRR；需要这些指标时应另行采集检索接口候选与排序标签，不能把文档命中率改名为召回率。

## 2026-09-23 本机基线

Docker 恢复后，RAGFlow 的 HTTP 接口虽然返回 200，但首题响应体为 code=400（Embedding 失败）。根因是 RAGFlow 配置指向宿主机 11528，而登录后 Ollama 仅在 11434 监听。在不停止已有实例和不重建知识库的条件下，另启动监听 11528、使用 D:/ollama/model 的项目专用 Ollama；容器内模型查询和真实 Chat 问答恢复。

第一轮有效结果保存在忽略目录 data/runtime-checks/knowledge-baseline.json：30 题，关键词代理 27，期望来源命中 24，无服务回退。复核发现服务规则库引用的是已部署的“检索优化版”文档，而部分样本仍期待旧文件名；隐私拒答也存在语义正确但关键词未逐字命中的情况。修订样本的允许文档名及措辞断言后，新的基线为 data/runtime-checks/knowledge-baseline-v2.json：30 题，关键词代理 28，期望来源命中 30，无服务回退。两版样本口径不同，**不能**将差值解释为检索质量提升；后续比较要求相同的样本指纹。剩余 KE-018、KE-027 为关键词措辞差异，人工复核其补课和隐私边界成立，仍保留机械失败记录。

本轮没有改动 RAGFlow 文档和检索参数，也没有做同一口径的前后知识质量提升对照。后续定向优化应先在当前基线固定样本下找真实错误，再调整材料或检索配置，并逐题人工复核。此处是 RAGFlow Chat 回答评测，不代表端到端 Supervisor 路由正确率或真实用户数据的准确率。

### 逐题人工复核结论

对原 30 题和扩展 12 题逐题阅读本机 RAGFlow 回答，核对被引用文档的相关规则片段；此处只记录合成样本编号和结论，不保存回答正文或真实家长对话。原集 KE-001 至 KE-017、KE-019 至 KE-021、KE-023 至 KE-026、KE-028 至 KE-030 未发现与知识边界冲突的承诺；KE-018/027 的机械误报及理由见审核文件。KE-022 问的是“快过期”，复问明确建议到期前联系教务、由教务审核，不承诺三个月；来源同时允许已过期后提交特殊处理申请，两种时间状态不可混为必须等到过期才申请。曾有一次回答仅提示过期后申请，措辞易误导，属于生成表达波动；本轮复问未复现，不把机械通过当成稳定性证明，保留为后续回归观察项。

扩展集 KE-031 至 KE-035、KE-037 至 KE-042 的回答均未发现直接越权、虚构实时名额或错误承诺；KE-034/039/040/041/042 的关键词机械失败包括班型名、省略“敏感信息”字样、以“无法提供”代替“不能提供”、人工核验同义表达等，不应自动改写答案或断言。KE-036 首次遗漏通常的 4 小时规则，属于确认的回答不完整；FAQ 定向补充并同步切片后，同指纹复问同时说明 4 小时与教务审核。以上是针对单轮合成样本的人工判断，不是多轮场景正确率；模型生成具有波动性，复测时须继续核对具体回答和证据。

人工记录只包含编号、受控原因、短处置和回归结论，不得复制真实对话、手机号或模型回答正文。在线输出保存在被忽略的 data/runtime-checks/；服务不可用时不写新基线。复测只比较相同样本指纹，生成措辞波动要人工核验后才能认定质量变化。
